## 0. 结论速览

| 问题 | 结论 |
|---|---|
| 该界面在哪里 | `t9s2t` 主窗体的引擎/模型区块（`btnDownloadModel` + `btnDeleteModel` + `lblEngine` + `lblStatus`） |
| 现在有几个触发点 | **只有 2 个**：启动时未就绪→显示+自动下载；就绪→隐藏到托盘 |
| 缺什么 | ① 无法从外部**指名**要打开哪个面板；② 模型"损坏"和"没装"混为一谈；③ `t9keyboard` 只看进程在不在，不知道模型能不能用；④ 用户想卸载模型只能自己找托盘图标 |

## 1. 先界定"该界面"是什么

`t9s2t` 主窗体（标题固定为 `小白T9语音输入 - 按住 Ctrl+Alt+D 开始语音输入`）里，与模型有关的就是这一块：

| 控件 | 三种形态 | 含义 |
|---|---|---|
| `btnDownloadModel` | `⬇️ 下载模型` | 引擎就绪、模型未装 → **安装态** |
| | `⚙️ 下载引擎组件`（橙底白字） | 引擎 DLL 缺失 → **先装引擎** |
| | `✅ 模型已就绪`（禁用） | 一切就绪 → **就绪态** |
| | `⬇️ 重新下载模型` | 识别失败时的补救 |
| `btnDeleteModel` | 就绪态可用 / 其余禁用 | **卸载入口** |
| `lblEngine` / `lblStatus` | 文案 | 状态与原因说明 |

判定依据（现有实现）：

```csharp
private readonly string modelPath = Path.Combine(AppDomain.CurrentDomain.BaseDirectory, "model");  // Form1.cs:28
private static readonly string[] RequiredEngineDlls = { "onnxruntime.dll", "sherpa-onnx-c-api.dll" };  // :466

AreEngineDllsReady()                  // 两个 DLL 存在且长度 > 0（还会顺手删掉 0 字节的坏文件）
EngineDetector.Detect(modelPath)      // 按目录里的文件结构识别引擎类型；None = 没有可用模型
```

## 2. 触发条件：什么时候该把界面显示出来

把"要不要显示"和"要不要自动下载"分开决策，是这个设计的核心。**下载 258MB 是重动作，只有用户主动启动程序时才该自动开始；被外部唤起的场合一律先展示、等用户点。**

| 编号 | 触发条件 | 判定依据 | 呈现形态 | 自动开始下载 |
|---|---|---|---|---|
| **T1** | 用户主动运行 `t9s2t.exe`，引擎或模型未就绪 | `!AreEngineDllsReady() \|\| Detect()==None` | 显示 + 安装态 | ✅ **是**（保持现有行为） |
| **T2** | 用户主动运行 `t9s2t.exe`，一切就绪 | 上条取反 | 隐藏到托盘 + 气泡"已就绪" | — |
| **T3** | **模型目录存在，但识别不出有效模型**（下载中断 / 解压半截 / 文件被截断） | `Directory.Exists(modelPath) && Detect()==None` | 显示 + **故障态**，文案要点明"上次安装未完成" | ❌ 否，先让用户确认（并提示将清理残留） |
| **T4** | **被 `t9keyboard` 唤起**（用户按了语音输入键，但模型不可用） | `t9keyboard` 侧判定（见 §4.3） | 显示 + 安装态 + 前置聚焦 | ❌ 否，等用户点 |
| **T5** | 用户主动要求**管理 / 卸载**模型 | 托盘菜单新增项"管理语音模型…" | 显示 + 就绪态（删除按钮可用） | — |
| **T6** | 自动下载重试全部失败 | `AutoSetupComponentsAsync` 重试耗尽 | 保持显示 + 橙色文案 + 手动重试 | — |
| **T7** | 运行期模型被外部删除 | 就绪态下周期性复查 `Detect()` | 回落到安装态 | ❌ 否 |
| **T8** | 用户再次双击 `t9s2t.exe` | 单实例分支 | 显示主窗口（**现有行为，保持**） | — |

> **T3 是当前最缺的一条。** 现在"目录存在但识别失败"和"完全没装"走的是同一个分支，用户看到的是"检测到缺少语音模型，即将自动下载"，而实际上硬盘上已经躺着一份 200MB 的残骸——既不告诉用户为什么，也不清理。

## 3. 展示逻辑

### 3.1 统一入口：面板意图

所有唤起路径收敛到一个方法，避免"每个入口各写一套显示代码"：

```csharp
/// <summary>打开模型面板的意图</summary>
internal enum ModelPanelIntent
{
    ShowOnly = 0,   // 只把主窗口调出来（保持与现有 WM_SHOWAPP 的兼容）
    Install  = 1,   // 安装：聚焦下载按钮；是否立刻开跑由 autoStart 决定
    Manage   = 2,   // 管理/卸载：聚焦删除按钮
}

private void ShowModelPanel(ModelPanelIntent intent, bool autoStartDownload)
{
    ForceShowMainWindow();                     // 已有的实现，含 AttachThreadInput 抢前台
    switch (intent)
    {
        case ModelPanelIntent.Install:
            lblStatus.Text = BuildInstallReasonText();   // 区分"缺引擎/缺模型/上次未完成"
            lblStatus.ForeColor = Color.FromArgb(200, 100, 0);
            btnDownloadModel.Focus();
            if (autoStartDownload) { /* 走 AutoSetupComponentsAsync */ }
            break;
        case ModelPanelIntent.Manage:
            lblStatus.Text = "模型已就绪。如需更换或释放空间，可删除后重新下载。";
            btnDeleteModel.Focus();
            break;
    }
}
```

### 3.2 进程内（首次启动）

```
Form1_Load
  ├─ 单实例检查（Global\t9s2t_single_instance_mutex_v3）
  │    已有实例 → SendMessage(WM_SHOWAPP, intent) → 退出
  ├─ 解析启动参数 → (intent, autoStart)
  ├─ 就绪检查
  │    ├─ 引擎✔ 模型✔   → 隐藏到托盘 + 气泡          （T2）
  │    ├─ 缺引擎 / 缺模型 → ShowModelPanel(Install, autoStart)  （T1 / T4）
  │    ├─ 目录在但识别不了 → ShowModelPanel(Install, false) + 故障文案  （T3）
  │    └─ 启动参数指定 Manage → ShowModelPanel(Manage, false)          （T5）
  └─ 无论如何都先装好键盘钩子与麦克风（现有实现已经这么做了，保持）
```

### 3.3 跨进程（已有实例在跑）

**复用现成的机制**，不新造轮子——`Form1_Load:163-169` 已经在用：

```csharp
IntPtr existingHandle = FindWindow(null, this.Text);
if (existingHandle != IntPtr.Zero) SendMessage(existingHandle, WM_SHOWAPP, IntPtr.Zero, IntPtr.Zero);
```

`WM_SHOWAPP = RegisterWindowMessage("WM_SHOWAPP_T9S2T_UNIQUE")`，`WndProc` 里转给 `ForceShowMainWindow()`。

**改动**：把意图塞进 `wParam`：

```csharp
// 发送端
SendMessage(existingHandle, WM_SHOWAPP, (IntPtr)(int)intent, IntPtr.Zero);

// 接收端
protected override void WndProc(ref Message m)
{
    if (m.Msg == WM_SHOWAPP)
        ShowModelPanel((ModelPanelIntent)m.WParam.ToInt32(), autoStartDownload: false);
    base.WndProc(ref m);
}
```

`wParam = 0` 即原来的 `ShowOnly`，**老版本发的消息依然兼容**。

### 3.4 命令行接口（给 `t9keyboard` 和快捷方式用）

`Program.cs` 目前**完全不处理参数**，建议补上：

| 命令行 | 意图 | 自动下载 |
|---|---|---|
| `t9s2t.exe` | 按现状（就绪则隐藏） | 就绪检查后决定 |
| `t9s2t.exe /model` | `Install` | ❌ |
| `t9s2t.exe /model /install` | `Install` | ✅ |
| `t9s2t.exe /manage` | `Manage` | — |

第二实例读到参数后，转发给第一实例再退出——这条路径的**完整性级别天然相同**，不受 §5.1 的 UIPI 限制。

### 3.5 把"能不能用"外泄给 `t9keyboard`

现在 `t9keyboard/Form1.cs:847` 的判定是：

```csharp
if (Process.GetProcessesByName("t9s2t").Length > 0) return true;   // ← 只要进程活着就说"可用"
```

模型正在下载、引擎缺失时，这里同样返回 `true`，用户按语音键**什么都不发生**。

建议 `t9s2t` 在状态变化时写一个约定位置：

```
HKCU\Software\Rime\Weasel\T9S2T
    EngineReady  REG_DWORD   0/1
    ModelReady   REG_DWORD   0/1
    ModelDir     REG_SZ      模型目录绝对路径
    UpdatedAt    REG_DWORD   Unix 时间戳（用于判断信息是否过期）
```

这样 `t9keyboard` 能给出**准确**的引导，而不是"启动了但没反应"。

## 4. 交互方式

### 4.1 安装（下载）流程

| 阶段 | 界面 | 用户操作 |
|---|---|---|
| 面板出现 | `lblStatus` 说明原因（缺引擎 / 缺模型 / **上次安装未完成**），`btnDownloadModel` 获得焦点 | — |
| 触发下载 | 点按钮 → 弹出**模型选择列表**（现有 `ShowDialog`，列出名称/大小/说明，远程列表失败会自动回落内置列表） | 选中 → "开始下载选中模型" |
| 下载中 | 按钮禁用 + 进度条 + `lblStatus` 进度文案 | *建议补：**取消**按钮*（现在没有） |
| 完成 | `SetModelReadyButtonState()` → `✅ 模型已就绪`、删除按钮启用、托盘气泡 | — |
| 失败 | 橙色文案 + 按钮恢复可点，可重试（引擎与模型各自的自动重试已有次数上限） | 点按钮手动重试 |

### 4.2 卸载流程

```
就绪态 → 点 btnDeleteModel
   → 确认框（建议补充信息，见下）
   → ① 先释放引擎  ② 再删目录
   → AutoCheckModel() 刷新 → 回到安装态 + 注册表 ModelReady=0
```

**⚠️ 现有实现有一个真实缺陷：释放和删除的顺序反了**（`Form1.cs:1358-1370`）：

```csharp
Directory.Delete(modelPath, true);            // ← 先删：此时 engine 仍持有模型文件句柄
engine?.Dispose(); engine = null;             // ← 后释放
```

ONNX Runtime 会持有 `model.int8.onnx` 等文件，Windows 上文件被占用时 `Directory.Delete` 会抛 `IOException`；而这里**没有 try/catch**，异常会直接冒到 UI 线程。建议改为：

```csharp
private void btnDeleteModel_Click(object sender, EventArgs e)
{
    if (!Directory.Exists(modelPath)) return;

    long sizeMB = 0;
    try { sizeMB = new DirectoryInfo(modelPath).EnumerateFiles("*", SearchOption.AllDirectories)
                          .Sum(f => f.Length) / 1024 / 1024; } catch { }

    var r = MessageBox.Show(
        $"将删除语音模型（约 {sizeMB} MB）：\n{modelPath}\n\n" +
        "删除后「按住 Ctrl+Alt+D 语音输入」将不可用，可随时重新下载。\n\n确定删除吗？",
        "删除语音模型", MessageBoxButtons.YesNo, MessageBoxIcon.Warning, MessageBoxDefaultButton.Button2);
    if (r != DialogResult.Yes) return;

    // 关键顺序：先把引擎和 VAD 释放掉，再删文件，否则文件被占用会删不掉
    try { engine?.Dispose(); } catch { }
    engine = null;
    vadProcessor = null;
    currentEngineType = EngineType.None;

    try
    {
        Directory.Delete(modelPath, true);
        lblStatus.Text = "🗑️ 模型已删除，可随时重新下载";
    }
    catch (Exception ex)
    {
        MessageBox.Show("删除失败：" + ex.Message + "\n\n请关闭其他正在使用模型的程序后重试。",
                        "删除失败", MessageBoxButtons.OK, MessageBoxIcon.Error);
    }
    _ = AutoCheckModel();      // 无论成功与否都刷新按钮状态
    SyncModelStateToRegistry();
}
```

### 4.3 从 `t9keyboard` 唤起时的交互（三态）

把 `CheckAndLaunchT9s2t()` 从"进程在不在"升级为三态：

| 状态 | 判定 | 动作 |
|---|---|---|
| 未运行 | `GetProcessesByName("t9s2t").Length == 0` | 弹确认框 → `Process.Start("t9s2t.exe /model")`（**会弹一次 UAC**，见 §5.2） |
| 在运行但模型不可用 | 注册表 `ModelReady == 0` | 提示"语音模型尚未就绪"，并提供按钮 → 唤起模型面板 |
| 在运行且就绪 | `ModelReady == 1` | 直接放行语音输入 |

**注意**：这里的提示框要有"打开模型管理界面 / 稍后再说"两个明确选项，而不是简单的一句"未在运行，是否启动"。用户此刻的诉求是"我要用语音输入"，你要告诉他**为什么不能用、怎么才能用**。

## 5. 权限与兼容性约束（这几条决定了方案能不能落地）

### 5.1 UIPI：普通权限进程**不能**向提权进程发自定义消息

`t9s2t` 的清单是 `requireAdministrator`（源码 `app.manifest` 与成品 `output\t9s2t\t9s2t.exe` 均已确认），它的完整性级别是 **High**；`t9keyboard` 是 **Medium**。

UIPI 的规则：低完整性进程向高完整性窗口发送**消息值 ≥ `WM_USER`(0x400)** 的消息会被拦截，而 `RegisterWindowMessage` 返回的 ID 落在 `0xC000–0xFFFF` 区间——**正好被拦**。

所以如果直接让 `t9keyboard` 对 `t9s2t` 的窗口 `SendMessage(WM_SHOWAPP, ...)`，**会静默失败**。

**解决办法（推荐第 1 条）**：

1. **`t9s2t` 侧主动放行**——窗口句柄创建后调一次：
   ```csharp
   [DllImport("user32.dll", SetLastError = true)]
   private static extern bool ChangeWindowMessageFilterEx(IntPtr hwnd, uint msg, uint action, IntPtr pChangeFilterStruct);
   private const uint MSGFLT_ALLOW = 1;
   // OnHandleCreated / Form1_Load 里：
   ChangeWindowMessageFilterEx(this.Handle, (uint)WM_SHOWAPP, MSGFLT_ALLOW, IntPtr.Zero);
   ```
   （Windows 7+ 可用；只需要放行这一条自定义消息，不要把面放开。）

2. **绕开消息**：让 `t9keyboard` 用 `Process.Start("t9s2t.exe /model")` 启一个**同权限级别**的新实例，由它自己去 `SendMessage` 给老实例。**代价是每次唤起都会弹一次 UAC。**

3. **不跨进程**：`t9keyboard` 只弹自己的提示框，用 `Process.Start`（`runas`）拉起 `t9s2t` 主界面，接受一次 UAC。

> 建议：**方案 1 做主路径**（体验最好、一次配置长期有效），**方案 3 作为兜底**（放行失败时还能用）。

### 5.2 启动 `t9s2t` 必然要过一次 UAC

`requireAdministrator` 决定了：只要它没在运行，任何方式的启动（包括 `Process.Start`）都会弹 UAC 同意框。设计交互时**不能假设"点一下就静默打开"**，要在文案里提前告知用户"接下来会请求管理员权限"。

### 5.3 `Global\` 互斥体：整机单实例

```csharp
_mutex = new Mutex(true, "Global\\t9s2t_single_instance_mutex_v3", out createdNew);
```

`Global\` 前缀是**跨会话**的。多用户机器（或"控制台 + 远程桌面"同时登录）时，第二个用户启动 `t9s2t` 会走到 `!createdNew` 分支 → `FindWindow` 找不到属于自己会话的窗口 → `Environment.Exit(0)`，**表现为"双击没反应"**。

如果不需要跨会话独占，改成 `Local\` 更合理；确实需要独占的话，`!createdNew` 分支要给出可见提示，别静默退出。

### 5.4 其他需要一并处理的点

| 项 | 现状 | 建议 |
|---|---|---|
| 下载取消 | **没有**（无 `CancellationToken`） | 258MB 下载应有"取消"，取消后要清理临时文件 |
| 磁盘空间检查 | **没有** | 开跑前检查 `DriveInfo.AvailableFreeSpace`，不足时给出明确提示而不是下到一半失败 |
| 下载中断残留 | 只是下次 `Detect()==None` 重新下 | 识别为 T3 并**主动清理残骸**后再下载 |
| 窗口标题依赖 | `FindWindow(null, this.Text)` 用完整标题字符串 | 把标题提成常量并加注释；标题一旦改动，跨进程唤起会静默失效 |
| 重复下载 | 已就绪时下载按钮禁用 | 保持；如需换模型，走"删除 → 重新下载" |
