# 算法服务（WeaselServer）开机自启改造说明

> 目标：让「小白T9输入法算法服务」快捷方式对应的程序（`WeaselServer.exe`）在开机登录后**可靠、静默、免 UAC** 地自动启动。
>
> 结论：把“启动动作”从 `HKLM\...\Run` 里的裸 exe，改为**已批准提权的计划任务**；原来的 Run 启动项**保留**，但改为“触发同一个任务”。两个入口指向同一个任务，因此既能双保险，又绝不会启动出第二份服务。

- 改造日期：2026-10-10
- 改动文件：`output\install.nsi`（GBK 编码）
- 备份：`output\install.nsi.bak-20261010`（md5 `5e09f58158c81cb1d8c000ee7f723bf8`）
- 涉及的快捷方式：`C:\ProgramData\Microsoft\Windows\Start Menu\Programs\小白T9输入法\小白T9输入法算法服务.lnk`
  （指向 `C:\Program Files\Rime\xiaobait9-2026.10.08\WeaselServer.exe`，无参数）

## 1. 改造前的现状（均为实测）

| 项 | 现状 | 问题 |
|---|---|---|
| exe 自身清单 | `WeaselServer.exe` **内嵌清单是 `asInvoker`** | 本身并不需要管理员 |
| 实际提权来源 | `install.nsi` 写入 `AppCompatFlags\Layers` → `RUNASADMIN` | 从此它**需要管理员令牌**（这是本 fork 有意为之：托盘菜单里的“重新部署/设置”会调用同样标了 RUNASADMIN 的 `WeaselDeployer.exe`，父进程已提权时子进程不会再弹 UAC） |
| 自启方式 | `HKLM\Software\Microsoft\Windows\CurrentVersion\Run\WeaselServer = "C:\...\WeaselServer.exe"` | 由外壳（Explorer）启动 → **登录阶段弹不出 UAC 同意窗口 → 被静默阻止**；只有 UAC 关闭或内置 Administrator 账户的机器才碰巧能起 |
| 路径引号 | 已带引号 ✔ | 无问题 |
| 失败重试 | 无 | 服务崩了当次登录不再恢复 |
| 卸载 | 已删除 Run 值 ✔ | 无问题 |

**根因与 numkeyboard 完全同类**：提权程序 + 用户级/外壳级启动项 = 结构性不可靠。

## 2. 关键风险：两个入口“直接启动同一个 exe”会互杀

这是本次改造**必须**处理的问题，否则“双保险”会变成“双故障”。

`WeaselServer.exe` 的启动流程（源码 `WeaselServer/WeaselServer.cpp:88-107`）：

```cpp
// restart if already running
{
  weasel::Client client;
  if (client.Connect())            // 连上已在运行的服务
  {
    client.ShutdownServer();       // ← 先把旧实例关掉
    if (quit) return 0;
    int retry = 0;
    while (client.Connect() && retry < 10) { client.ShutdownServer(); retry++; Sleep(50); }
    if (retry >= 10) return 0;     // ← 旧实例 500ms 内没退干净，新实例直接退出
  }
}
```

而单实例保护在 `WeaselIPCServer/WeaselServerImpl.cpp:142-151`（命名互斥体 `(WEASEL)Furandōru-Sukāretto-<用户名>`，`ERROR_ALREADY_EXISTS` 或 `ERROR_ACCESS_DENIED` 都视为“已在运行”）。

由此得到两个结论：

1. **后启动的实例会先杀掉先启动的实例再接管** —— 不是“检测到已运行就退出”。
2. 如果旧实例在 **500 ms** 内没退干净（`WeaselServer` 退出要 `Finalize()` 保存用户词典、释放 Rime 引擎，很可能超过 500 ms），新实例会放弃退出，**而旧实例已经收到停止指令了** → 极端情况下**两个都没了**，算法服务彻底不启动。

所以：**Run 项和计划任务不能都直接指向 `WeaselServer.exe`。** 必须让二者走同一个“闸门”。

## 3. 改造后的启动链路

```
 用户登录
    │
    ├─(A) HKLM\...\Run\WeaselServer ──► wscript.exe //B weasel-autostart.vbs
    │                                     │ 睡 60 秒（避开登录高峰，让主通道先走）
    │                                     ├─ tasklist 发现服务已在跑？→ 什么都不做
    │                                     └─ 否则 schtasks /run → 触发任务（同为兜底）
    │
    └─(B) 计划任务 XiaoBaiT9\WeaselServer （登录触发，延迟 30 秒）★主通道
             RunLevel = HighestAvailable → 静默取得管理员令牌，不弹 UAC
                       │
                       ▼
             "C:\...\WeaselServer.exe"（提权令牌，满足 RUNASADMIN）
                       │
       运行中 ─────────┴──── 失败重启 3 次 / 每次 1 分钟；执行时长不限

 手动：开始菜单「算法服务」快捷方式 ──► schtasks /run /tn "XiaoBaiT9\WeaselServer"
                                          （同样走任务，双击不弹 UAC）
```

**为什么这样就安全**：任务设置了 `MultipleInstancesPolicy = IgnoreNew`，且 `WeaselServer` 会一直运行 → **任务实例的状态始终是“正在运行”**。此时任何再次触发（Run 项兜底、手动点快捷方式、重复登录）都会被任务计划程序直接忽略，**连进程都不会创建**，自然不存在互杀。

### 4.4 新增两个函数（插在 `.onGUIEnd` 之后）

- `TrimTail`：清洗 `whoami` 输出尾部的 CR/LF/空格。
- `RegisterWeaselServerTask`：取当前用户 → 生成 UTF-16LE 任务 XML → `schtasks /Create /XML /F` → 生成兜底脚本 `weasel-autostart.vbs` → 写 Run 项。

生成的兜底脚本（`$INSTDIR\weasel-autostart.vbs`，纯 ASCII）：

```vbs
WScript.Sleep 60000
Set sh = CreateObject("WScript.Shell")
If sh.Run("cmd /c tasklist /FI ""IMAGENAME eq WeaselServer.exe"" | find /I ""WeaselServer.exe""", 0, True) <> 0 Then
  If sh.Run("schtasks.exe /run /tn ""XiaoBaiT9\WeaselServer""", 0, True) <> 0 Then
    sh.Run """C:\Program Files\Rime\xiaobait9-2026.10.08\WeaselServer.exe""", 0, False
  End If
End If
```

`wscript.exe` 是 GUI 子系统程序，**不创建控制台窗口**，所以启动项不会闪黑框。

## 5. 计划任务配置项逐条说明

任务名：`XiaoBaiT9\WeaselServer`（自动创建 `XiaoBaiT9` 文件夹）

| XML 字段 | 值 | 为什么这么设 |
|---|---|---|
| `Triggers/LogonTrigger/Delay` | `PT30S` | 等外壳、托盘、网络栈就绪，避开登录风暴；`WeaselServer` 启动时要加载 Rime 引擎与词典，IO 很重 |
| `LogonTrigger/UserId` | `计算机名\用户名`（`whoami` 结果） | 只对这个用户生效；多用户机器见 §6 |
| `Principals/LogonType` | `InteractiveToken` | “只在用户登录时运行” → 进程在用户会话里，**才有托盘图标**；不需要保存密码 |
| `Principals/RunLevel` | `HighestAvailable` | **关键**：任务启动时直接使用完整管理员令牌，`RUNASADMIN` 得到满足且**不弹 UAC**（UAC 弹窗只在“要求提权但当前是普通令牌”时才出现） |
| `MultipleInstancesPolicy` | `IgnoreNew` | 幂等闸门：任务已在运行时不启动新实例 → 双入口/重复触发天然安全 |
| `ExecutionTimeLimit` | `PT0S` | **必须显式写**。默认是 `PT72H`（3 天），超时任务计划程序会结束任务并杀掉进程 —— 常驻服务会被“莫名其妙”关掉 |
| `RestartOnFailure` | 1 分钟 / 3 次 | 进程非 0 退出（崩溃）时自动拉起 |
| `DisallowStartIfOnBatteries` | `false` | **笔记本必须**，否则“只有插电才启动” |
| `StopIfGoingOnBatteries` | `false` | 同上，防止拔电即被杀 |
| `StartWhenAvailable` | `true` | 错过的触发（睡眠/关机）在可用时补跑 |
| `RunOnlyIfNetworkAvailable` | `false` | 本服务不需要网络，别被网络条件卡住 |
| `AllowStartOnDemand` | `true` | 允许被 `/run` 按需触发（快捷方式依赖这一条） |
| `Actions/Exec/Command` | `$INSTDIR\WeaselServer.exe` | 路径与参数分字段，天然避免“未加引号”类解析问题 |
| `Actions/Exec/WorkingDirectory` | `$INSTDIR` | 与“程序文件夹”一致 |

> XML 只用 Task Scheduler **1.2** 元素（Win7 SP1+ 都认）；未使用 `UseUnifiedSchedulingEngine`、`DisallowStartOnRemoteAppSession` 等 Win8+ 专有项。

## 6. 权限与兼容性注意事项

### 6.1 任务 XML 的编码（最容易踩的坑）

`schtasks /Create /XML` **只接受 UTF-16**。用 UTF-8/ANSI 写会直接报 **“任务 XML 格式不正确”**。

本次实现：`FileWriteByte 255` + `FileWriteByte 254` 写 BOM（`FF FE`），再用 `FileWriteUTF16LE` 写正文。
**已在本机实测**：生成的文件头 `ff fe 3c 00`、XML 可解析、中文（GBK 源文件 → UTF-16 输出）完全正确。

### 6.2 用户名 / 多用户

- 任务绑定**安装时的当前用户**（`whoami` 结果）。
- 如果安装器是通过“**其他用户的凭据**”提权运行的（OTS），`whoami` 会返回那个管理员账户 → 任务注册到错误的用户名下。**必须以当前登录用户自己的管理员身份安装。**
- 多用户共用一台机器时：任务只对该用户生效。要让所有用户都自动启动，把 XML 里的
  `<UserId>$R2</UserId>`（Principal 与 LogonTrigger 各一处）换成 `<GroupId>S-1-5-32-545</GroupId>`（Users 组），并删掉 `LogonTrigger` 里的 `<UserId>`。

### 6.3 标准用户账户

标准用户登录时，`HighestAvailable` 只能给他自己的普通令牌 → `RUNASADMIN` 的程序**可能仍起不来**（Windows 设计，无法静默绕过）。
原来的 Run 项在标准用户下同样起不来，因此**不构成退步**。若必须支持标准用户，只能去掉 `RUNASADMIN`（放弃托盘菜单里“重新部署/设置”的免 UAC 特性）。

### 6.4 任务计划服务被禁用 / 安全软件拦截

- 若 `Task Scheduler` 服务被禁用或组策略禁止创建任务，`schtasks /Create` 会失败。安装日志（`nsExec::ExecToLog` 的输出）里能看到具体错误。
- 此时兜底脚本 `weasel-autostart.vbs` 会退化为“直接启动 exe”（可能弹一次 UAC），不会彻底失效。
- 部分安全软件会把“创建提权计划任务”判为可疑行为并拦截；任务描述里已写明用途，必要时请用户加白。

### 6.5 安装目录带版本号

安装目录形如 `$INSTDIR\xiaobait9-<版本>`，每次升级都会变。`/Create ... /F` 每次安装都会**覆盖重建**任务，路径自动同步；无需手工维护。

### 6.6 注册表视图（Run 键重定向）

32 位进程写 `HKLM\Software\...` 会被重定向到 `WOW6432Node`，而**自启只读非重定向的那一份**。原脚本已用 `SetRegView 64/32` 处理，本次改动**保留**了这个逻辑（函数内也自行设置并按 `SetRegView lastused` 复原）。

### 6.7 快捷方式行为变化（需知）

| 场景 | 改前 | 改后 |
|---|---|---|
| 服务未运行，双击快捷方式 | 弹 UAC → 确认后启动 | **无 UAC**，直接启动 |
| 服务已在运行，双击快捷方式 | 弹 UAC → 确认后**重启服务** | 任务被 `IgnoreNew` 忽略，**服务不重启**（schtasks 窗口一闪即退，可视为“无反应”） |
| 想重启服务 | — | 用托盘菜单退出后再启动，或直接 `weasel-autostart.vbs` 的逻辑 |

### 6.8 VBScript 依赖

兜底脚本用 VBScript（`wscript.exe`，Windows 7–11 均自带，且无控制台窗口）。微软已宣布逐步弃用 VBScript，但目前（Win11 24H2）仍默认可用。**即使 VBScript 将来被移除，主通道（计划任务）不受影响**，只是少了一层兜底。

### 6.9 XML 特殊字符

如果用户自定义的安装路径含 `&`、`<`、`>`，写进 XML 会破坏格式。默认路径（`C:\Program Files\Rime\xiaobait9-<版本>`）不含这些字符；如需支持，要在 `RegisterWeaselServerTask` 里对 `$INSTDIR` 做 XML 转义。

## 附：为什么不是别的方案

| 备选方案 | 为什么不用 |
|---|---|
| 保持 `HKLM\Run` 指向 exe + 另加计划任务 | 两个入口各自启动 exe → 互杀，可能“同归于尽”（见 §2） |
| 把 Run 项删掉、只留任务 | 可行且更简洁；但用户明确要求保留原启动项，故保留为兜底 |
| 注册成 Windows 服务 | `WeaselServer` 需要交互式桌面（托盘图标 + 与用户会话的 IPC），服务在会话 0 跑不了托盘；虽然源码里存在 `WeaselService` 框架，但当前未启用 |
| 去掉 `RUNASADMIN` 让它以普通权限运行 | exe 清单本就是 `asInvoker`，技术上可行；但托盘菜单里的 `WeaselDeployer.exe`（同样标了 RUNASADMIN）就会每次弹 UAC，属功能退步 |
| 启动文件夹放快捷方式 | 同样受“登录阶段无法弹 UAC”限制，且不解决互杀 |
