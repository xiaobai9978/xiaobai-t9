# numkeyboard 开机自启：可靠性分析与改造方案

> 结论先行：**当前实现是"结构性不可靠"，不是"偶尔失灵"。**
> 根因是「`requireAdministrator` 清单」与「`HKCU\...\Run` 登录自启」这两件事在 Windows 上互斥——
> 登录阶段外壳无法弹出 UAC 同意窗口，所以提权程序从 Run 键/启动文件夹启动会被静默阻止或干脆起不来。
> 另外还有 4 个次级缺陷（无参数、无引号、陈旧路径不刷新、状态判断只看存在性）会各自独立地造成"看起来设了自启，实际没起来"。
>
> 建议方案：**改用「计划任务 + 最高权限 + 登录延迟 30s + 失败重启」**，
> 由程序自己（本身就是提权的）负责注册，安装器负责清理旧项与首次拉起，卸载器负责删除。
> 长期可考虑「降权改造」（配置搬到 `%APPDATA%`，清单改 `asInvoker`），从根上不再需要提权。

- 分析日期：2026-10-10
- 分析对象：`C:\weasel\numkeyboard`（net4.8 / WinForms / AnyCPU）
- 相关文件：`numkeyboard/Program.cs`、`numkeyboard/Form1.cs`、`numkeyboard/Properties/app.manifest`、`..\output\install.nsi`

## 0. TL;DR

| 项 | 现状 | 风险 | 建议 |
|---|---|---|---|
| 自启机制 | `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 写 `NumKeyboardTray` | **P0 结构性失效**：exe 是 `requireAdministrator`，登录时不弹 UAC 也起不来 | 换成计划任务（`RunLevel=HighestAvailable`） |
| 启动参数 | 只写 `Application.ExecutablePath`，**不带 `-background`** | 代码里准备好的静默启动路径完全没被用到，登录时会闪一下窗口 | 任务 Action 加 `-background` |
| 路径引号 | 未加引号 | 安装目录 `C:\Program Files\Rime\xiaobait9-<ver>\` 含空格；未加引号存在解析歧义与劫持面 | 一律加引号（t9s2t 已修过同一问题） |
| 路径刷新 | 只在"值不存在"时写入，存在就永不更新 | 本机现指向 `bin\Debug\numkeyboard.exe`（开发产物），一旦被清理，自启永久失效且勾选框仍显示已勾选 | 每次启动校验路径，不一致即重建 |
| 状态判断 | `IsAutoRunEnabled()` 只判断值是否存在 | 任务管理器/安全软件把启动项禁用后，UI 仍显示"已开启" | 查真实启用状态（任务 `Enabled` / `StartupApproved`） |
| 失败重试 | 无 | 进程崩溃 / 被结束 → 本次登录内不再恢复 | 任务 `RestartOnFailure` + 可选重复触发看门狗 |
| 开机托盘图标 | `WndProc` 里的 `TaskbarCreated` 分支被 `this.Visible` 挡住 | 开机静默启动后托盘区没有图标，用户找不到入口 | 解除与窗口可见性的耦合，并重试重建 |
| 崩溃表现 | 未处理异常走 .NET 默认对话框 | 无人点"退出"时进程既不退出也不干活，任何重启策略都不会触发 | 接管异常 → 写日志 + 非 0 退出 |
| 升级换目录 | 安装目录带版本号 `xiaobait9-<ver>` | 升级后任务/Run 指向旧目录 | 启动时自愈重建 + 安装器幂等重注册 |
| 卸载 | 卸载器**完全不清理** numkeyboard 自启项 | 残留死项，每次登录都尝试启动一个已删除的 exe | 卸载段删除任务与 Run 值 |

## 1. 现状实证

### 1.1 代码：只有一条出口，写注册表

`numkeyboard/Form1.cs:313-315`（`#region 托盘和自启`）：

```csharp
private bool IsAutoRunEnabled() { using (var key = Microsoft.Computer.Registry.CurrentUser.OpenSubKey(@"Software\Microsoft\Windows\CurrentVersion\Run", false)) return key?.GetValue("NumKeyboardTray") != null; }
private void SetAutoRun(bool enable) { using (var key = ...OpenSubKey(..., true)) { if (enable) key.SetValue("NumKeyboardTray", Application.ExecutablePath); else key.DeleteValue("NumKeyboardTray", false); } }
private void checkBox1_CheckedChanged(object sender, EventArgs e) { SetAutoRun(checkBox1.Checked); }
```

`numkeyboard/Form1.cs:209-216`（`Form1_Load`）：

```csharp
// 如果检测到当前没有开启自启，则默认帮他勾上并写入注册表
if (!IsAutoRunEnabled())
{
    SetAutoRun(true);
}
checkBox1.Checked = IsAutoRunEnabled();
checkBox1.CheckedChanged += checkBox1_CheckedChanged;
```

→ **只在"值不存在"时写入**；路径变了、指向的 exe 被删了，都不会修正。

### 1.2 代码：`-background` 参数已经实现，但两条启动路径都没用

`numkeyboard/Program.cs:65-88` 与 `Form1`：

```csharp
string[] args = Environment.GetCommandLineArgs();
if (args.Contains("-background")) isBackgroundStart = true;

protected override void SetVisibleCore(bool value)
{
    if (isFirstShow && isBackgroundStart) { isFirstShow = false; base.SetVisibleCore(false); }

但：
- `SetAutoRun` 写的是 `Application.ExecutablePath`（裸路径，无参数）
- `output/install.nsi:374` 的启动菜单快捷方式也是 `"$INSTDIR\numkeyboard.exe" ""`（无参数）

→ 这个静默启动分支实际上是**死代码**。启动后要靠 `Form1_Load` 尾部的 `WindowState = Minimized; ShowInTaskbar = false; BeginInvoke(Hide)` 兜底，登录时会有一瞬间的窗口/任务栏闪动。

### 1.3 二进制：清单要求管理员

对 `output\numkeyboard.exe`（1874992 字节）与安装目录 `C:\Program Files\Rime\xiaobait9-2026.10.08\numkeyboard.exe` 做字符串扫描，二者都命中内嵌清单：

```

```

来源：`numkeyboard/Properties/app.manifest:19`。

**这就是"为什么必须是管理员"**：配置写在安装目录 `data\numkeyboard.txt`（`Form1.cs:31-32`），而安装目录在 `Program Files` 下，且清单里声明了 `requestedExecutionLevel` → 关闭了 UAC 文件/注册表虚拟化 → 普通权限写不进去。

### 1.4 本机注册表现场（实测）

```

1. 指向 **Debug 产物**，不是安装版（`C:\Program Files\Rime\xiaobait9-2026.10.08\numkeyboard.exe`）
2. **没有引号**

→ WeaselServer 这条是**带引号**的（历史教训已经吸取过一次），numkeyboard 这条没有。

计划任务：`Get-ScheduledTask` 中匹配 `num|t9|weasel|xiaobai|keyboard` 的结果为空 → **当前没有任何计划任务**。

## 2. 可靠性问题清单（按严重度）

### P0-1　提权程序 + 登录自启 = 结构性冲突（本轮的主因）

Windows 的外壳在登录阶段**无法显示 UAC 同意窗口**，因此从 `Run` 键或"启动"文件夹启动的程序，如果其清单要求提权，会被静默阻止/直接失败。表现随环境漂移：

| 环境 | 表现 |
|---|---|
| UAC 开启（默认）+ 管理员账户 | 登录后弹一次 UAC（用户不点就不起来），或被阻止 |
| UAC 开启 + 标准用户账户 | 起不来（无法 OTS 提权），无任何提示 |
| UAC 关闭 / 内置 Administrator 账户 | **碰巧能起来** |

→ 这就是"有的机器行、有的机器不行、重装又好了"的来源。**必须换机制，不能靠改注册表写法解决。**

### P0-2　静默启动参数没接上

见 1.2。属于"代码写好了但没接线"，改起来零风险。

### P0-3　Run 值未加引号

安装目录 `C:\Program Files\Rime\xiaobait9-2026.10.08\` 含空格。未加引号时 Windows 会按空格逐个前缀试探解析（`C:\Program.exe` → `C:\Program Files\Rime.exe` → …），这也是经典的"未加引号服务路径"劫持面。**t9s2t 已经栽过一次并修好（`t9s2t/Form1.cs:265` 注释写着"必须加引号"），numkeyboard 没跟上。**

### P0-4　陈旧路径永不刷新（本机正在发生）

值存在即跳过写入 → 本机自启指向 `bin\Debug`。一旦开发目录被清理，登录自启静默失效，而 UI 里勾选框依然是勾上的。**这是"用户以为有自启、其实没有"的最常见来源。**

### P0-5　启用状态判断失真

`IsAutoRunEnabled()` 只判断"值存在"。但 Windows 从 Win8 起把 Run 项的启用状态独立存放在：

```
HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\StartupApproved\Run
```

用户在「任务管理器 → 启动应用」里关掉后，值还在，程序依然显示"已开启"。第三方启动管理软件（360、火绒等）也会这样静默禁用。

### P1-6　没有失败重试

进程崩溃、被安全软件结束、被用户在任务管理器里杀掉 —— 本次登录内不会恢复。

### P1-7　开机无托盘图标

见 1.6。自启"成功"了，但用户找不到它。

### P1-8　崩溃时进程挂着不退（会吃掉所有重试机会）

`Main` 里没有接管 `Application.ThreadException` / `AppDomain.UnhandledException`。.NET Framework 的默认行为是**弹一个未处理异常对话框并把进程留在那里**。若无人点击，进程既不退出也不工作 —— 于是"进程存在"导致计划任务的 `IgnoreNew`/`RestartOnFailure` 全都不会触发。**这条必须和"失败重试"一起改，否则重试机制是空的。**

### P1-9　升级换目录后自启指向旧目录

安装目录形如 `$INSTDIR\xiaobait9-<version>`（`install.nsi:17`），每次升级都换路径。自启项里的绝对路径必须跟着更新，否则升级=自启失效。

### P1-10　卸载不清理自启项

`install.nsi` 卸载段没有删除 `HKCU\...\Run\NumKeyboardTray`（将来也没有任务）。残留死项。

### P2-11　每次手动启动都弹 UAC（体验税）

双开 `requireAdministrator` 的代价：用户每次从开始菜单启动都要点一次 UAC。若走"降权改造"（方案 B）可以彻底消除。

### P2-12　多用户 / 多会话

`HKCU` 只对当前用户有效；远程桌面会话与本地会话的 `Local\` 互斥量互不干扰（各自一份钩子），这是**正确**行为，但意味着任务要以"交互式登录的那个用户"为 `UserId`，不能用服务账户。

## 3. 方案设计

### 3.1 机制选型对比

| 机制 | 静默提权 | 需要管理员 | 支持延迟 | 失败重启 | 用户可见/可管理 | 适用性 |
|---|---|---|---|---|---|---|
| `HKCU\...\Run`（现状） | ❌ | 否 | ❌ | ❌ | 任务管理器可见 | **不适用于提权程序** |
| "启动"文件夹快捷方式 | ❌（快捷方式的"以管理员身份运行"在自启时同样被阻止） | 否 | ❌ | ❌ | 可见 | 仅适用于降权程序 |
| `HKLM\...\Run` | ❌ | 写需要 | ❌ | ❌ | 可见 | 同上 |
| **计划任务（推荐）** | ✅ `RunLevel=HighestAvailable` | 注册时需要 | ✅ `Delay` | ✅ `RestartOnFailure` + 重复触发 | 任务计划程序可见 | **本方案** |
| Windows 服务 | ✅ | 需要 | ✅ | ✅（服务恢复） | 不可见 | 不适用：会话 0 无桌面，托盘/键盘钩子看不见用户输入 |

> 关键理由：numkeyboard 需要**交互式桌面**（托盘图标 + `WH_KEYBOARD_LL` 钩子 + `keybd_event` 注入），所以只能用"登录时触发"的交互式任务，不能用服务、也不能用"计算机启动时"（会话 0）。

### 3.2 推荐架构

```
                    ┌──────────────────────────────────────────┐
   用户登录  ──────▶ │ 计划任务 XiaoBaiT9\NumKeyboardTray        │
                    │  · 触发器：我的登录 + 延迟 30s             │
                    │  · 权限：最高（HighestAvailable）          │
                    │  · 动作："...\numkeyboard.exe" -background │
                    │  · 失败重启 3 次 / 每次 1 分钟             │
                    │  · 执行时限：不限（PT0S，默认 3 天会杀进程）│
                    └───────────────┬──────────────────────────┘
                                    ▼
                    numkeyboard.exe -background
                                    ▼
                 ① 单实例互斥量（已有）→ 已在跑就静默退出
                 ② 隐藏主窗口（SetVisibleCore 拦截，已有）
                 ③ 3s 定时轮询 VID/PID → 插上键盘就装钩子（已有）
                 ④ 写启动日志：谁拉起的、是否提权、自启项自检结果
                 ⑤ 托盘图标常显（需修复）
                                    │
         崩溃 / 被杀 ───────────────┘─▶ 任务重启（≤1 分钟）或下次登录
```

**职责划分（重要：只有一处真相）**

| 组件 | 职责 |
|---|---|
| **应用（`AutoStartManager.cs`，新增）** | 唯一实现：生成任务 XML、`schtasks /Create /XML /F` 注册、`/Delete` 注销、查询真实状态、路径自愈、清理老 Run 项 |
| **安装器（install.nsi）** | ① 清理老版本残留（Run 值 + 旧任务）；② 装完后台拉起 `numkeyboard.exe -background`，让它自己注册；③ 卸载时删除任务与 Run 值 |
| **不再需要** | Run 键写入逻辑（`SetAutoRun` 删除或降级为 fallback） |

**降级链**（防止"任务计划服务被禁用/被安全软件拦"这类环境）

```
计划任务注册失败（或当前非提权）
   → 回退写 HKCU\...\Run，格式为 "C:\...\numkeyboard.exe" -background（带引号）
   → 同时在 UI/日志上明确提示"当前离线环境只能降级自启，登录时可能需要确认 UAC"
```

### 3.3 启动时序与"为什么是 30 秒"

| 时刻 | 事件 | 说明 |
|---|---|---|
| T+0 | 用户登录 | 外壳开始加载 |
| T+0~20s | Explorer / 托盘区 / 输入法 / 一堆 Run 项同时启动 | 这段是资源争抢高峰期，此时启动容易抢不到 CPU，也容易拿不到托盘 |
| T+30s | 任务触发 | `Delay=PT30S`；托盘区此时已就绪，`TaskbarCreated` 之后重建图标才有效 |
| T+30s+ | 进程启动 → 装钩子（带 3s 轮询重试） | 设备检测走 WMI，登录初期 WMI 可能未就绪，靠轮询自愈 |

延迟是"启动时机"的核心手段；比在应用里 `Thread.Sleep` 更好——不占进程、不占内存，且不触发任务计划程序的 3 天执行时限计时。

### 3.4 计划任务 XML（完整）

字段逐个说明见下表。存放为 `XiaoBaiT9NumKeyboard.task.template.xml`（占位符 `__USER__` / `__EXE__` / `__WORKDIR__`）。

```xml
<?xml version="1.0" encoding="UTF-16"?>
<Task version="1.2" xmlns="http://schemas.microsoft.com/windows/2004/02/mit/task">
  <RegistrationInfo>
    <Author>xiaobai.pro</Author>
    <Description>小白T9输入法 - 小键盘驱动开机自启（最高权限，无 UAC 提示）</Description>
  </RegistrationInfo>
  <Triggers>
    <LogonTrigger>
      <Enabled>true</Enabled>
      <UserId>__USER__</UserId>
      <Delay>PT30S</Delay>
    </LogonTrigger>
  </Triggers>
  <Principals>
    <Principal id="Author">
      <UserId>__USER__</UserId>
      <LogonType>InteractiveToken</LogonType>
      <RunLevel>HighestAvailable</RunLevel>
    </Principal>
  </Principals>
  <Settings>
    <MultipleInstancesPolicy>IgnoreNew</MultipleInstancesPolicy>
    <DisallowStartIfOnBatteries>false</DisallowStartIfOnBatteries>
    <StopIfGoingOnBatteries>false</StopIfGoingOnBatteries>
    <AllowHardTerminate>true</AllowHardTerminate>
    <StartWhenAvailable>true</StartWhenAvailable>
    <RunOnlyIfNetworkAvailable>false</RunOnlyIfNetworkAvailable>
    <IdleSettings>
      <StopOnIdleEnd>false</StopOnIdleEnd>
      <RestartOnIdle>false</RestartOnIdle>
    </IdleSettings>
    <AllowStartOnDemand>true</AllowStartOnDemand>
    <Enabled>true</Enabled>
    <Hidden>false</Hidden>
    <RunOnlyIfIdle>false</RunOnlyIfIdle>
    <WakeToRun>false</WakeToRun>
    <ExecutionTimeLimit>PT0S</ExecutionTimeLimit>
    <Priority>7</Priority>
    <RestartOnFailure>
      <Interval>PT1M</Interval>
      <Count>3</Count>
    </RestartOnFailure>
  </Settings>
  <Actions Context="Author">
    <Exec>
      <Command>__EXE__</Command>
      <Arguments>-background</Arguments>
      <WorkingDirectory>__WORKDIR__</WorkingDirectory>
    </Exec>
  </Actions>
</Task>
```

| 字段 | 值 | 为什么 |
|---|---|---|
| `LogonTrigger/Delay` | `PT30S` | 等外壳/托盘就绪，避开登录高峰（可调，见 §6.2） |
| `UserId` | `计算机名\用户名` | 必须是**交互式登录的那个用户**；不要用 SYSTEM（会话 0 无桌面） |
| `LogonType` | `InteractiveToken` | "只在用户登录时运行"，进程才有交互桌面 |
| `RunLevel` | `HighestAvailable` | **本方案的关键**：任务启动时直接用完整管理员令牌，`requireAdministrator` 清单得到满足且不弹 UAC |
| `MultipleInstancesPolicy` | `IgnoreNew` | 重复触发/重复登录不会叠出第二个实例（与应用内互斥量双保险） |
| `ExecutionTimeLimit` | `PT0S` | **必须显式写**：默认是 3 天，超时任务计划程序会结束任务（杀掉进程） |
| `RestartOnFailure` | 1 分钟 / 3 次 | 进程非 0 退出（崩溃）时自动拉起 |
| `DisallowStartIfOnBatteries` / `StopIfGoingOnBatteries` | `false` | 笔记本上不加这两条会"插电才启动"，是极常见的暗坑 |
| `StartWhenAvailable` | `true` | 错过的触发（睡眠/关机）在可用时补跑 |
| `RunOnlyIfNetworkAvailable` | `false` | 本程序不需要网络，别被网络条件卡住 |
| `Command` / `Arguments` | 分开写 | 路径与参数分字段，天然避免"未加引号"和解析歧义 |
| `WorkingDirectory` | 安装目录 | 与 `AppDomain.BaseDirectory` 一致（配置在 `data\` 下） |

> 兼容性：只用 Task Scheduler 1.2 元素，Win7 SP1+ 可用。
> **不要**加 `UseUnifiedSchedulingEngine`（Win8+ 专有）、`DisallowStartOnRemoteAppSession`（Win8+ 专有）。
> XML 必须存成 **UTF-16LE（带 BOM）**，用 UTF-8 存 `schtasks /Create /XML` 会直接报"任务 XML 格式不正确"。

### 4.1 新增 `numkeyboard/AutoStartManager.cs`

```csharp
using System;
using System.Diagnostics;
using System.IO;
using System.Security;
using System.Security.Principal;
using System.Text;
using System.Text.RegularExpressions;
using System.Windows.Forms;
using Microsoft.Win32;

namespace NumKeyboardTray
{
    internal enum AutoStartState { Task, RunKeyFallback, Disabled, Failed }

    /// <summary>
    /// 开机自启统一入口（计划任务方案）。
    ///
    /// 为什么不用 HKCU\...\Run：
    ///   本程序清单为 requireAdministrator，登录阶段外壳无法弹出 UAC 同意窗口，
    ///   提权程序从 Run 键/启动文件夹启动会被静默阻止；计划任务以 RunLevel=HighestAvailable
    ///   启动可静默取得管理员令牌，并自带延迟触发与失败重启。
    /// </summary>
    internal static class AutoStartManager
    {
        public const string TaskName = @"XiaoBaiT9\NumKeyboardTray";
        private const string TaskDesc = "小白T9输入法 - 小键盘驱动开机自启（最高权限，无 UAC 提示）";
        private const string RunKeyPath = @"Software\Microsoft\Windows\CurrentVersion\Run";
        private const string RunValueName = "NumKeyboardTray";   // 与老版本同名，便于迁移
        private const string StartArg = "-background";
        private const string LogonDelay = "PT30S";               // 想更早启动就调小，见文档 §6.2

        private static string ExePath { get { return Application.ExecutablePath; } }
        private static string WorkDir { get { return AppDomain.CurrentDomain.BaseDirectory.TrimEnd('\\'); } }
        private static string TempXml { get { return Path.Combine(Path.GetTempPath(), "xiaobait9-numkeyboard.task.xml"); } }
        private static string SchTasks { get { return "schtasks.exe"; } }   // 走 PATH，32/64 位宿主一致

        public static bool IsElevated
        {
            get { using (var id = WindowsIdentity.GetCurrent()) return new WindowsPrincipal(id).IsInRole(WindowsBuiltInRole.Administrator); }
        }

        // ---------------- 查询 ----------------

        /// <summary>任务已注册、处于启用状态，且 Command 指向当前 exe；否则回落到 Run 键判断。</summary>
        public static AutoStartState Query()
        {
            string xml;
            if (Run(SchTasks, "/Query /TN \"" + TaskName + "\" /XML", out xml) == 0)
            {
                bool disabled = Regex.IsMatch(xml, @"<Enabled>\s*false\s*</Enabled>", RegexOptions.IgnoreCase);
                string cmd = ExtractTag(xml, "Command");
                bool sameExe = cmd != null && string.Equals(cmd.Trim().Trim('"'), ExePath, StringComparison.OrdinalIgnoreCase);
                if (!disabled && sameExe) return AutoStartState.Task;   // 指向旧版本目录同样判定为需重建
            }
            using (var k = Registry.CurrentUser.OpenSubKey(RunKeyPath, false))
            {
                if (k != null && k.GetValue(RunValueName) != null) return AutoStartState.RunKeyFallback;
            }
            return AutoStartState.Disabled;
        }

        public static bool IsEnabled() { return Query() != AutoStartState.Disabled; }

        // ---------------- 写入 ----------------

        public static AutoStartState Apply(bool enable, out string message)
        {
            message = null;
            if (!enable)
            {
                Run(SchTasks, "/Delete /TN \"" + TaskName + "\" /F", out message);
                DeleteRunValue();
                return AutoStartState.Disabled;
            }

            if (IsElevated)
            {
                try
                {
                    // schtasks 只接受 UTF-16；用 UTF-8 写会报"任务 XML 格式不正确"
                    File.WriteAllText(TempXml, BuildTaskXml(), new UnicodeEncoding(false, true));
                    if (Run(SchTasks, "/Create /TN \"" + TaskName + "\" /XML \"" + TempXml + "\" /F", out message) == 0)
                        return AutoStartState.Task;
                }
                catch (Exception ex) { message = ex.Message; }
                message = "计划任务注册失败，已降级为注册表自启（登录时可能需要确认 UAC）：" + message;
            }
            else
            {
                message = "当前进程未提权，只能降级为注册表自启（登录时可能需要确认 UAC）。";
            }

            // 降级：HKCU\Run —— 必须带引号 + -background，否则含空格的安装路径会解析出错
            try
            {
                using (var k = Registry.CurrentUser.CreateSubKey(RunKeyPath))
                    k.SetValue(RunValueName, "\"" + ExePath + "\" " + StartArg, RegistryValueKind.String);
                return AutoStartState.RunKeyFallback;
            }
            catch (Exception ex) { message = "注册表自启同样失败：" + ex.Message; return AutoStartState.Failed; }
        }

        /// <summary>清理老版本遗留的 Run 项（升级迁移用）。</summary>
        public static void DeleteRunValue()
        {
            try { using (var k = Registry.CurrentUser.OpenSubKey(RunKeyPath, true)) if (k != null) k.DeleteValue(RunValueName, false); }
            catch { }
        }

        // ---------------- 内部 ----------------

        private static string BuildTaskXml()
        {
            string exe = SecurityElement.Escape(ExePath);
            string dir = SecurityElement.Escape(WorkDir);
            string user = SecurityElement.Escape(WindowsIdentity.GetCurrent().Name);
            string desc = SecurityElement.Escape(TaskDesc);
            return string.Format(
@"<?xml version=""1.0"" encoding=""UTF-16""?>
<Task version=""1.2"" xmlns=""http://schemas.microsoft.com/windows/2004/02/mit/task"">
  <RegistrationInfo><Author>xiaobai.pro</Author><Description>{4}</Description></RegistrationInfo>
  <Triggers>
    <LogonTrigger><Enabled>true</Enabled><UserId>{2}</UserId><Delay>{3}</Delay></LogonTrigger>
  </Triggers>
  <Principals>
    <Principal id=""Author"">
      <UserId>{2}</UserId><LogonType>InteractiveToken</LogonType><RunLevel>HighestAvailable</RunLevel>
    </Principal>
  </Principals>
  <Settings>
    <MultipleInstancesPolicy>IgnoreNew</MultipleInstancesPolicy>
    <DisallowStartIfOnBatteries>false</DisallowStartIfOnBatteries>
    <StopIfGoingOnBatteries>false</StopIfGoingOnBatteries>
    <AllowHardTerminate>true</AllowHardTerminate>
    <StartWhenAvailable>true</StartWhenAvailable>
    <RunOnlyIfNetworkAvailable>false</RunOnlyIfNetworkAvailable>
    <IdleSettings><StopOnIdleEnd>false</StopOnIdleEnd><RestartOnIdle>false</RestartOnIdle></IdleSettings>
    <AllowStartOnDemand>true</AllowStartOnDemand>
    <Enabled>true</Enabled><Hidden>false</Hidden><RunOnlyIfIdle>false</RunOnlyIfIdle><WakeToRun>false</WakeToRun>
    <ExecutionTimeLimit>PT0S</ExecutionTimeLimit>
    <Priority>7</Priority>
    <RestartOnFailure><Interval>PT1M</Interval><Count>3</Count></RestartOnFailure>
  </Settings>
  <Actions Context=""Author"">
    <Exec>
      <Command>{0}</Command>
      <Arguments>" + StartArg + @"</Arguments>
      <WorkingDirectory>{1}</WorkingDirectory>
    </Exec>
  </Actions>
</Task>", exe, dir, user, LogonDelay, desc);
        }

        private static string ExtractTag(string xml, string tag)
        {
            var m = Regex.Match(xml, "<" + tag + @">([\s\S]*?)</" + tag + ">", RegexOptions.IgnoreCase);
            return m.Success ? m.Groups[1].Value : null;
        }

        private static int Run(string file, string args, out string output)
        {
            output = "";
            try
            {
                var psi = new ProcessStartInfo(file, args)
                {
                    UseShellExecute = false,
                    CreateNoWindow = true,
                    RedirectStandardOutput = true,
                    RedirectStandardError = true,
                    StandardOutputEncoding = Encoding.Default,   // schtasks 走控制台代码页(中文系统=936)
                    StandardErrorEncoding = Encoding.Default
                };
                using (var p = Process.Start(psi))
                {
                    var sb = new StringBuilder();
                    p.OutputDataReceived += (s, e) => { if (e.Data != null) sb.AppendLine(e.Data); };
                    p.ErrorDataReceived += (s, e) => { if (e.Data != null) sb.AppendLine(e.Data); };
                    p.BeginOutputReadLine();
                    p.BeginErrorReadLine();
                    if (!p.WaitForExit(15000)) { try { p.Kill(); } catch { } return -1; }
                    output = sb.ToString();
                    return p.ExitCode;
                }
            }
            catch (Exception ex) { output = ex.Message; return -1; }
        }
    }
}
```

要点：
- **`Query()` 除了看任务是否存在，还校验 `Command` 是否指向当前 exe** → 版本目录变了会被判定为"需重建"，这正是 P1-9 的自愈。
- 注册失败自动降级到 Run 键（带引号 + 参数），并把降级原因回传给调用方显示。
- `schtasks` 输出用 `Encoding.Default` 解码，避免中文用户名/路径乱码。

## 6. 四类常见问题的应对

### 6.1 启动权限

| 场景 | 对策 |
|---|---|
| **管理员账户 + UAC 开启（主流）** | 计划任务 `RunLevel=HighestAvailable` → 静默提权，`requireAdministrator` 清单被满足，无 UAC 弹窗 |
| **管理员账户 + UAC 关闭** | 同样走任务，行为一致（不要再依赖这个"碰巧能行"的环境） |
| **标准用户账户** | 计划任务的 `HighestAvailable` 只能给他自己的普通令牌 → 提权 exe 仍起不来（Windows 设计如此，无法静默绕过）。**唯一出路是 §7 的降权改造** |
| **安装器用"其他管理员凭据"提权（OTS）** | `WindowsIdentity.GetCurrent().Name` 会返回**那个管理员账户**，任务会注册到错误的人名下。要在文档/安装包里明确：必须以**当前登录用户自己的管理员身份**安装；代码里如需更稳，可改用 `GetShellWindow` 反查 Explorer 的进程属主作为 `UserId` |
| **非提权进程调用自启设置** | `Apply()` 自动降级到 Run 键，并在托盘气泡里说明原因，不静默失败 |

### 6.2 启动时机

| 问题 | 对策 |
|---|---|
| 启动太早，托盘没就绪 → 没图标 | 触发器 `Delay=PT30S`；同时修好 `TaskbarCreated` 分支（§4.3c），Explorer 重启后也能挂回图标 |
| 启动太早，WMI 未就绪 → 设备检测失败 | 已有 3 秒轮询（`monitorTimer`）会自愈，无需改；但应把"检测失败"写进日志，便于区分"没插键盘"与"检测不了" |
| 用户希望更快 | 把 `LogonDelay` 调到 `PT10S`；托盘图标那条修复能覆盖更早启动的情况 |
| 希望"进系统就有"（未登录） | **不要**改成"计算机启动时"：那是会话 0，没有交互桌面，托盘和键盘钩子都无效 |
| 睡眠/休眠恢复 | 触发器只针对登录；休眠恢复不影响已运行进程。若进程在睡眠中被结束，靠 `RestartOnFailure` 或下一次登录恢复 |
| 远程桌面二次登录 | 每个会话一份实例（`Local\` 互斥量按会话隔离），属正确行为；`IgnoreNew` 只挡同一会话内的重复触发 |

### 6.3 系统环境差异

| 差异 | 影响 | 对策 |
|---|---|---|
| 安装路径含空格（`Program Files`） | Run 键裸路径解析歧义 | 任务用 `Command`/`Arguments` 分字段；降级 Run 键也强制加引号 |
| 安装目录带版本号 `xiaobait9-<ver>` | 升级后自启指向旧目录 | `Query()` 校验 exe 路径，不一致即重建；安装器每次 `/F` 重注册 |
| Win7 SP1 vs Win10/11 | XML 元素兼容性 | 只用 Task Scheduler 1.2 元素；避免 `UseUnifiedSchedulingEngine` 等 Win8+ 专有项 |
| 32/64 位 | 32 位宿主下 `schtasks`/`SystemDirectory` 命中 SysWOW64 | 行为一致；如要统一位数，加 `<Prefer32Bit>false</Prefer32Bit>` 并回归钩子功能 |
| 中文用户名/中文路径 | XML 编码 & 控制台输出编码 | XML 写 UTF-16LE+BOM；`schtasks` 输出按 `Encoding.Default`(936) 解码 |
| 任务计划服务被禁用/被裁剪系统 | 注册失败 | 降级到 Run 键 + UI 明确提示（不静默） |
| 安全软件（360/火绒等） | 会把"创建提权计划任务"判为可疑并拦截；也会静默禁用 Run 项 | 任务名/描述写清用途；把"注册失败"当正常分支处理并提示用户加白 |
| 多用户共用电脑 | 任务只对注册时的用户生效 | 每用户首次运行各自注册；不要指望一次安装服务所有人 |
| 系统还原/克隆镜像 | 任务里的 `UserId` 变成旧机器名 | `Query()` 发现 `Command` 或用户不匹配 → 重建。可在启动日志里记录 `UserId` 便于排障 |

### 6.4 启动失败与重试（分层）

| 层 | 失败形态 | 恢复手段 | 恢复时间 |
|---|---|---|---|
| L1 进程崩溃/被杀 | 非 0 退出 | 任务 `RestartOnFailure`（1 分钟 × 3 次） | ≤1 分钟 |
| L2 进程"假活"（UI 线程异常但没退） | 进程在、功能无 | **靠 §4.2 接管异常 + 非 0 退出**，把它变成 L1 | 立即 |
| L3 功能性失败（钩子装不上、设备检测失败） | 进程在、改键无效 | 应用内 3 秒轮询重试（已有）；日志记录失败原因 | ≤3 秒 |
| L4 任务整体没触发（错过登录窗口、被禁用） | 无进程 | `StartWhenAvailable=true` + 下次登录；UI 勾选框反映真实状态 | 下次登录 |
| L5 需要"绝对不掉线" | 任意 | 加固版：给同一任务的 `LogonTrigger` 加 `<Repetition><Interval>PT5M</Interval><Duration>PT24H</Duration><StopAtDurationEnd>false</StopAtDurationEnd></Repetition>`。健康时 `IgnoreNew` 会直接忽略重复触发（不产生多余进程），进程一死则 ≤5 分钟被拉起 | ≤5 分钟 |

> **加固版必须配套一件事**：用户在托盘点「退出」后，看门狗会在 5 分钟内把它拉回来，等于"退出失效"。
> 处理办法：退出时写一个"本登录会话已主动退出"的标记（用登录会话的唯一标识，如
> `GetTokenInformation(TokenStatistics).AuthenticationId` 这个 LUID），
> `Program.cs` 在 `-background` 且标记匹配当前会话时直接静默退出。
> 不加这套标记就别开看门狗（基础版已经能覆盖绝大多数场景）。

**可观测性**（决定"能不能定位"）：

```cmd
:: 任务状态、上次运行结果、下次运行时间
schtasks /Query /TN "XiaoBaiT9\NumKeyboardTray" /V /FO LIST

:: 任务计划程序事件日志（Win8+ 默认开启）
wevtutil qe Microsoft-Windows-TaskScheduler/Operational /c:20 /rd:true /f:text
```

`LastRunResult` 对照：`0x0` 成功；`0x1`/`0x2` 执行失败或路径不存在；`0x41301` 正在运行；`0x80070424` 任务计划服务不可用。

## 附录 A：降权改造（方案 B，根治，可选）

如果愿意接受一次较大的回归成本，可以让 numkeyboard **彻底不需要管理员权限**，自启就回到最简单的形态（启动文件夹快捷方式 / Run 键，永不弹 UAC、永不被拦）。

需要动的地方：

| 项 | 现状 | 改造 |
|---|---|---|
| `Properties\app.manifest:19` | `requireAdministrator` | 改 `asInvoker` |
| 配置路径 `Form1.cs:31-32` | `<安装目录>\data\numkeyboard.txt` | `%APPDATA%\XiaoBaiT9NumKeyboard\numkeyboard.txt`，首次启动从旧位置迁移 |
| `Registry.SetValue(HKCU\Control Panel\Desktop, LowLevelHooksTimeout)` | 提权下写 | HKCU 普通权限即可写，无需改 |
| `SetWindowsHookEx(WH_KEYBOARD_LL)` | — | **不需要提权** |
| WMI `Win32_PnPEntity` 查询 | — | **不需要提权** |
| `SystemParametersInfo(SPI_SETMOUSEKEYS)` | — | **不需要提权** |
| `keybd_event` 注入 | — | 注入到**提权的**窗口（任务管理器等）会被 UIPI 拦；普通应用场景不受影响。这是本方案唯一的真实功能损失 |
| 自启 | 计划任务 | `shell:startup` 快捷方式（带 `-background`）或 HKCU Run（带引号+参数），两者都由非提权进程写入 |

判断标准：如果你的用户群里有人用**标准账户**、或者你希望"再也不弹 UAC"，就走 B；
否则 A 的收益/成本比更好，且不改变任何既有行为。
