# t9keyboard「双击打不开」排查报告

- 排查对象：`C:\weasel\output\t9keyboard.exe`（753,664 字节，构建时间 2026-10-10 15:16）
- 排查时间：2026-10-10 15:20
- 排查方式：**实机运行 + 窗口枚举**（三轮对照实验），非纯静态推理

---

## 一、直接结论

> **不是「首次打开不显示」。**
> 首次双击时，软键盘和悬浮窗**都会正常创建并显示**（实验一已证实）。
>
> 真正的问题是：**当已经有一个实例在运行时，再双击 exe 会静默退出——0.05 秒、退出码 0、不弹任何提示、也不会把已有窗口调出来**。
> 用户视角看就是"双击没反应/打不开"。而且如果此时软键盘恰好是隐藏状态（比如刚双击过悬浮窗），双击 exe **永远无法把它重新调出来**。

## 三、根因分析

### 根因 1（主因）：单实例分支静默退出，且激活逻辑失效

`Program.cs:26-35`：

```csharp
_mutex = new Mutex(true, SingleInstanceMutexName, out bool isFirstInstance);
if (!isFirstInstance)
{
    ActivateExistingWindow();   // ← 这里没起作用
    return;                     // ← 直接退出，没有任何用户可见反馈
}
```

`Program.cs:86-99` 的实现：

```csharp
private static void ActivateExistingWindow()
{
    Process current = Process.GetCurrentProcess();
    foreach (Process process in Process.GetProcessesByName(current.ProcessName))
    {
        if (process.Id != current.Id && process.MainWindowHandle != IntPtr.Zero)
        {
            if (IsIconic(process.MainWindowHandle))
                ShowWindow(process.MainWindowHandle, SW_RESTORE);
            SetForegroundWindow(process.MainWindowHandle);
            return;
        }
    }
}
```

这里有三处缺陷，任何一处都足以让"双击没反应"：

| # | 缺陷 | 后果 |
|---|---|---|
| ① | `Process.MainWindowHandle` **只返回可见的顶层窗口**（.NET 内部按 `IsWindowVisible` 过滤） | 软键盘被 `Hide()` 后，它返回的是那个 50×50 的半透明悬浮窗，而不是键盘 |
| ② | 只处理了**最小化**（`IsIconic` → `SW_RESTORE`），**完全没处理被 `Hide()` 隐藏**的情况 | 隐藏的键盘永远不会被 `ShowWindow(SW_SHOW)` 调出来 |
| ③ | `Form2` 带 `WS_EX_NOACTIVATE`，`SetForegroundWindow` 对它本来就不生效；且非前台进程调用 `SetForegroundWindow` 会被系统拒绝 | 即使找到了窗口，也不会有任何视觉变化 |

**三个缺陷叠加的结果**：双击 exe → 进程 0.05 秒退出 → 屏幕上什么都不发生。

### 根因 2（次级）：`isKeyboardVisible` 与实际可见性不同步

`Form2.cs:77`：

```csharp
bool isKeyboardVisible = true;        // ← 硬编码初值，此后只在 button1_Click 里翻转
```

而软键盘的显示/隐藏**不止一个入口**。`help.cs:575-576`（设置窗口点"确定"）也会显示键盘：

```csharp
keyboard f4 = Form2.FindOrCreateForm<keyboard>();
f4.Show();                            // ← 键盘显示了，但 Form2.isKeyboardVisible 没同步
```

**复现路径**：

1. 启动 → 键盘显示，`isKeyboardVisible = true`
2. 双击悬浮窗 → 键盘隐藏，`isKeyboardVisible = false`
3. 右键 → 帮助与设置 → 点「确定」→ 键盘**被显示**，但标志**仍是 false**
4. 双击悬浮窗想隐藏键盘 → 走到 `else` 分支执行 `ShowKeyboard()`（键盘本来就显示着，无事发生）→ **第一次双击看起来"没反应"**
5. 再双击一次 → 才真正隐藏

**这才是真正意义上的"点了没反应、要按两次"**。它的触发条件是键盘可见性与那个布尔标志不同步。

### 与本次「贴边收起」新功能的交叉影响

新功能会让悬浮窗在贴边后收起成 **6px 窄条**。如果用户此时想通过"双击 exe"重新找到程序，恰好撞上根因 1 —— **完全没有任何反馈**，比之前更容易被误判成"程序坏了"。

（悬浮窗位置不做持久化，重启程序后会回到屏幕中央，所以不是"上次拖到边上导致这次看不见"。）

## 四、怎么快速判断你遇到的是哪一种

| 现象 | 对应根因 |
|---|---|
| 双击 exe → 毫无反应；**任务管理器里有 `t9keyboard.exe` 在跑** | 根因 1（实例已在运行） |
| 双击 exe → 毫无反应；**任务管理器里没有该进程** | 需要看事件日志/首次运行路径（见第五节 A） |
| 双击悬浮窗 → 第一次没反应，再点一次才行 | 根因 2（状态标志不同步） |
| 程序起来了，但只看到 50×50 半透明小方块、没有键盘 | 键盘被隐藏了 → 双击悬浮窗即可；或键盘窗口被拖到屏幕外 |

**一条命令定位**（任务管理器 → 详细信息，或 PowerShell）：

```powershell
Get-Process t9keyboard -ErrorAction SilentlyContinue | Select-Object Id, StartTime
```

**有进程 = 根因 1；没进程 = 需要继续查首次启动路径。**

## 五、修复建议

### 修复 1：让第二实例真的能把窗口调出来（改 `Program.cs`）

核心思路：**改用 `FindWindow` 按窗口标题找——它对已隐藏的窗口同样有效**，而 `Process.MainWindowHandle` 不行；再用 `AttachThreadInput` 绕过"非前台进程不能抢焦点"的系统限制（`t9s2t` 里已有同样写法）。

```csharp
[DllImport("user32.dll", CharSet = CharSet.Auto)]
private static extern IntPtr FindWindow(string lpClassName, string lpWindowName);
[DllImport("user32.dll")]
private static extern bool IsWindowVisible(IntPtr hWnd);
[DllImport("user32.dll")]
private static extern bool BringWindowToTop(IntPtr hWnd);
[DllImport("user32.dll")]
private static extern IntPtr GetForegroundWindow();
[DllImport("user32.dll")]
private static extern uint GetWindowThreadProcessId(IntPtr hWnd, out uint pid);
[DllImport("kernel32.dll")]
private static extern uint GetCurrentThreadId();
[DllImport("user32.dll")]
private static extern bool AttachThreadInput(uint idAttach, uint idAttachTo, bool fAttach);

private const int SW_SHOW = 5;

private static void ActivateExistingWindow()
{
    // ① FindWindow 对「已隐藏」的窗口一样能找到；MainWindowHandle 只认可见窗口，会漏掉隐藏的键盘
    IntPtr target = FindWindow(null, "小白T9软键盘");

    // ② 键盘窗体还没建出来时（启动极早期）退化为按进程找
    if (target == IntPtr.Zero)
    {
        Process cur = Process.GetCurrentProcess();
        foreach (Process p in Process.GetProcessesByName(cur.ProcessName))
        {
            if (p.Id == cur.Id) continue;
            if (p.MainWindowHandle != IntPtr.Zero) { target = p.MainWindowHandle; break; }
        }
    }

    if (target == IntPtr.Zero)
    {
        MessageBox.Show(
            "小白T9软键盘已经在运行。\n\n如果找不到它：\n" +
            "· 悬浮图标可能已贴边收起 —— 把鼠标移到屏幕边缘的窄条上即可展开\n" +
            "· 键盘本身可能被隐藏 —— 双击悬浮图标可切换显示",
            "小白T9软键盘", MessageBoxButtons.OK, MessageBoxIcon.Information);
        return;
    }

    if (!IsWindowVisible(target)) ShowWindow(target, SW_SHOW);   // 被 Hide() 过 → 先显示出来
    if (IsIconic(target)) ShowWindow(target, SW_RESTORE);        // 最小化 → 还原

    // ③ SetForegroundWindow 从非前台进程调用会被系统拒绝，靠 AttachThreadInput 提高成功率
    uint fgThread = GetWindowThreadProcessId(GetForegroundWindow(), out uint _);
    uint myThread = GetCurrentThreadId();
    bool attached = false;
    if (fgThread != 0 && fgThread != myThread)
        attached = AttachThreadInput(fgThread, myThread, true);
    try
    {
        SetForegroundWindow(target);
        BringWindowToTop(target);
    }
    finally
    {
        if (attached) AttachThreadInput(fgThread, myThread, false);
    }
}
```

> 即便 `SetForegroundWindow` 仍被拒绝，至少 `ShowWindow(SW_SHOW)` 已经把键盘显示出来了，用户一定能看到。

### 修复 2：别缓存键盘可见性（改 `Form2.cs`）

```csharp
// 删掉：bool isKeyboardVisible = true;

/// <summary>直接查真实可见性，避免与其它入口（如设置窗口的"确定"）不同步</summary>
private bool IsKeyboardReallyVisible()
{
    foreach (Form form in Application.OpenForms)
        if ((form is keyboard || form is numboard || form is enboard) && form.Visible)
            return true;
    return false;
}

private void button1_Click(object sender, EventArgs e)
{
    if (DockHandleClick()) return;          // 贴边收起：收起状态下点击=展开

    if (timer1.Enabled)
    {
        timer1.Enabled = false;
        timer1.Tag = null;
        if (IsKeyboardReallyVisible()) HideKeyboard();
        else                           ShowKeyboard();
        // 不再维护 isKeyboardVisible
    }
    else
    {
        timer1.Enabled = true;
        timer1.Tag = DateTime.Now;
    }
}
```

### 修复 3（可选）：给用户一个"到底点没点上"的反馈

如果不想动 `ActivateExistingWindow`，至少在 `!isFirstInstance` 分支里加一句 `MessageBox` 或气泡提示，而不是静默 `return`。**"静默失败"是这个 bug 里最伤人的部分**——用户无法区分"程序坏了"和"程序已经在跑"。
