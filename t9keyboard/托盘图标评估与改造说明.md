> **有必要保留，但改造前它只是个"半成品"。**

## 三、必要性评估

### 3.1 支持保留的理由（3 条，第 1 条最关键）

1. **它是程序唯一"常驻可见"的入口。**
   软键盘本体可以被隐藏（双击悬浮窗切换），悬浮窗又能**贴边收起成 6px 窄条**。
   一旦两者都不可见，用户手里就没有任何可点的东西了——
   按上一轮排查（`双击打不开-排查报告.md`）的结论，**此时再双击 exe 会被单实例 mutex 静默吞掉，屏幕上什么都不会发生**。
   也就是说：**托盘图标是唯一稳定的"我还能操作这个程序"的出口。**

2. **热键切换是"看不见的状态变化"，需要反馈。**
   按热键会启用/停用键盘钩子（改键功能开关），这个状态在界面上没有任何体现。
   气泡通知是合适的反馈手段——这部分设计是站得住的。

3. **Windows 的交互惯例**：托盘的图标，用户默认它会响应右键。一个右键无反应的图标，用户会怀疑程序卡死了。

### 3.2 改造前存在的问题

| 问题 | 说明 |
|---|---|
| 右键无菜单 | 违反系统惯例；用户右键后毫无反馈（最严重的一条） |
| 气泡文案说错了对象 | 代码切换的是 **`KeyboardHook`（改键功能）** 的启停，文案却写"**快捷键**已释放/已注册"，容易被理解成"热键失效了" |
| tooltip 是死字符串 | 永远显示"小白T9输入法软键盘通知"，不反映当前钩子是开是关 |
| 职责错位 | 一个"通知图标"挂在"设置窗口"上，而设置窗口本身是会被隐藏的——图标能活着纯属组件生命周期的副作用 |

**结论：不是"要不要存在"，而是"必须补上操作能力"。**

## 四、已实施的改造

### 4.1 托盘图标右键菜单（新增）

```
显示悬浮按钮        ← 把被贴边收起的悬浮窗完整摆出来（8 秒内不自动收起）
帮助与设置          ← 打开设置窗口（双击托盘图标同效）
────────────────
退出软键盘          ← 二次确认后退出
```

**为什么菜单里要有"显示悬浮按钮"**：悬浮窗支持贴边收起（缩成 6px 窄条），收起来之后用户很难再点到它。
这是**唯一的救援入口**，也是让这个图标真正"有用"的关键一项。
（用户只点名要"退出软键盘"，这一项是配套的必要补充——否则"图标有用"这件事只解决了一半。）

**关于"退出软键盘"**：加了二次确认，并把默认按钮设为「否」。
理由是软键盘退出后悬浮按钮也会一起消失，误点的代价是"得重新启动程序"，值得多问一句。

### 4.2 配套改动：`Form2.RestoreFloatingIcon()`

```csharp
public void RestoreFloatingIcon()
{
    _dockHoldUntil = DateTime.Now.AddMilliseconds(DockHoldAfterRestoreMs);  // 8 秒内不自动收起
    _dockLeaveAt = DateTime.MinValue;
    if (_dockEdge != DockEdge.None && _dockCollapsed) ExpandFromDock();
    if (!this.Visible) this.Show();
    try { this.BringToFront(); } catch { }
}
```

新增常量 `DockHoldAfterRestoreMs = 8000`，并在悬停轮询里加一道闸：
```csharp
if (DateTime.Now < _dockHoldUntil) return;   // 刚从托盘菜单唤出，先别急着缩回去
```

**必须要有这个"暂缓自动收起"**：否则用户点了"显示悬浮按钮"，窗口展开后在鼠标没移上去的 0.6 秒内又自动缩回 6px——等于白点。

### 4.3 气泡文案修正

| 场景 | 改前 | 改后 |
|---|---|---|
| 停用键盘钩子 | `快捷键已释放。` | `改键功能已暂停（再按一次 Ctrl+H 恢复）` |
| 启用键盘钩子 | `快捷键已注册！！` | `改键功能已恢复` |
| tooltip | 固定 `小白T9输入法软键盘通知` | 随状态变：`小白T9软键盘 - 改键运行中` / `- 改键已暂停` |

热键名从 `textBox1.Text` 读取（读不到就退化为"热键"两字），不写死。
