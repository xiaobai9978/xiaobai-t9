# t9keyboard 半透明悬浮窗「贴边收起」功能说明

> 目标控件：**`Form2`**（`t9keyboard` 启动后显示的那个 50×50 半透明圆形悬浮图标）
> 改动日期：2026-10-10　·　改动文件：新增 `Form2.EdgeDock.cs`，修改 `Form2.cs`、`t9keyboard.csproj`

---

## 1. 控件定位（改造前的现状）

`Program.cs:40` 把 `Form2` 作为主窗体 `Application.Run`，它就是那个常驻的半透明悬浮窗：

| 属性 | 值 | 说明 |
|---|---|---|
| `ClientSize` | 50×50 | 整个窗口就是一个按钮大小 |
| `FormBorderStyle` | None | 无边框 |
| `Opacity` | 0.4 | **半透明外观的来源** |
| `BackColor` + `TransparencyKey` | White | 白色区域变透明（且点击穿透） |
| `TopMost` / `ShowInTaskbar` | true / false | 置顶、不占任务栏 |
| `button1` | 0,0 大小 50×50 | 铺满窗口，白底彩色风车 logo（`BackgroundImageLayout=Stretch`） |
| 扩展样式 | `WS_EX_NOACTIVATE \| WS_EX_TOOLWINDOW` | 不抢焦点、不出现在 Alt+Tab |

原有交互：**左键拖动**移动窗口、**单击**（400ms 计时）目前不做任何事、**双击**隐藏/显示整个软键盘、**右键**弹出「帮助与设置 / 退出软键盘」菜单。

## 2. 交互规格（本次新增）

### 2.1 触发条件

| 动作 | 条件 | 结果 |
|---|---|---|
| **吸附** | 拖动松手时，窗口任一边到「鼠标所在显示器的工作区（已排除任务栏）」对应边的距离 **≤ 20px**（已越界拖出屏幕也算） | 判定贴该边，吸附到位 |
| **自动收起** | 已吸附 **且** 鼠标不在窗口范围内 **且** 持续 **600ms** | 沿该边滑出，只留 **6px** 窄条 |
| **悬停展开** | 收起状态下鼠标移到露出的窄条上（120ms 轮询发现） | 立即滑回完整显示 |
| **点击展开** | 收起状态下单击一下 | 同上，并吞掉这次点击（500ms 内不再参与双击判定） |
| **取消吸附** | 把窗口拖到离边缘 **> 20px** 的位置松手 | 不再自动收起，保持自由摆放 |

> **为什么用轮询而不是 `MouseEnter` / `MouseLeave`**：窗口用 `TransparencyKey = White` 把白色区域做成了**点击穿透**，收起后只剩 6px 而且其中约一半像素是透明的（实测 45.7% 不透明），靠鼠标事件会漏判。改用 120ms 轮询 `Cursor.Position` 判定，稳定得多。

### 2.2 收起方向

由吸附的那条边决定，四条边都支持：

| 吸附边 | 收起后窗口位置（`wa` = 工作区） | 露出的窄条 |
|---|---|---|
| 左 | `X = wa.Left - (宽 - 6)` | 屏幕左侧竖条 |
| 右 | `X = wa.Right - 6` | 屏幕右侧竖条 |
| 上 | `Y = wa.Top - (高 - 6)` | 屏幕顶部横条 |
| 下 | `Y = wa.Bottom - 6` | 屏幕底部横条 |

实测这四条边的中段都有实色像素（左蓝 / 上橙 / 右绿 / 下黄），6px 窄条里约 **46%** 是不透明像素，肉眼可见，不会"缩进去就找不着"。

### 2.3 动画过渡

- 统一的 `Timer`，**15ms/帧（≈66fps）**，总时长 **160ms**
- 缓动函数 `easeOutCubic`：`k = 1 - (1 - t)³`（起步快、收尾稳）
- 逐帧插值 `Location`，结束后精确落到目标点（消除浮点误差）
- 吸附那一下距离很短（≤20px），同样是 160ms，观感就是"啪"地贴上去
- 动画期间暂停悬停判定，避免中途被反向打断；拖动会立即中止动画

### 2.4 与原有交互的接缝

| 原有行为 | 保留情况 |
|---|---|
| 左键拖动 | 保留。从收起状态按下时会**先瞬时恢复完整显示**，再重新计算拖动基准，所以不会"拖着半个窗口跑" |
| 双击切换键盘显隐 | 保留。收起状态下的第一下点击只会展开（并吞掉 500ms 内的点击），避免"双击窄条"被误判成切换键盘 |
| 单击（原为空操作） | 现在承担"收起状态 → 展开" |
| 右键菜单 | 完全不动 |
| `Opacity` / `TransparencyKey` / `TopMost` / `WS_EX_*` | 完全不动 |

## 3. 实现结构

### 3.1 新增 `Form2.EdgeDock.cs`（`partial class Form2`）

刻意独立成一个文件，不改动 `Form2.cs` 的原有代码逻辑，便于单独回滚：

```csharp
public partial class Form2
{
    private enum DockEdge { None, Left, Right, Top, Bottom }

    private void AttachEdgeDock()                    // 在 Form2_Load 里挂接
    private void DockBeginDrag()                     // 拖动开始：退出收起状态
    private void button1_MouseUp_Dock(...)           // 松手：判定吸附
    private void dockHoverTimer_Tick(...)            // 120ms 轮询：展开 / 收起
    private bool DockHandleClick()                   // 点击：收起状态 → 展开
    private void CollapseToDock() / ExpandFromDock()
    private Point ExpandedLocation(Rectangle wa)     // 贴边且完整显示的位置
    private Point CollapsedLocation(Rectangle wa)    // 收起后的位置
    private void AnimateTo(Point target, bool endsCollapsed)
    private void dockAnimTimer_Tick(...)             // 逐帧动画
    private Screen DockScreen() / Rectangle DockWorkArea()
    private void OnDisplaySettingsChanged(...)       // 分辨率 / 显示器变化
}
```

所有 Timer 都在 `AttachEdgeDock()` 里运行时创建（**不放进 Designer，字段初始化器里也不做任何有副作用的事**），因此不会影响 VS 窗体设计器的加载——这一点对这个项目很重要（`help` 的静态字段曾导致设计器打不开）。

### 3.2 `Form2.cs` 只加 3 行接入

```csharp
// ① Form2_Load 末尾
AttachEdgeDock();

// ② button1_MouseDown 左键分支，记录 offset 之前
DockBeginDrag();

// ③ button1_Click 开头
if (DockHandleClick()) return;
```

### 3.3 `t9keyboard.csproj`

```xml
<Compile Include="Form2.Designer.cs">
  <DependentUpon>Form2.cs</DependentUpon>
</Compile>
<Compile Include="Form2.EdgeDock.cs" />     <!-- 新增 -->
```

## 4. 可调参数（都在 `Form2.EdgeDock.cs` 顶部）

| 常量 | 默认值 | 含义 / 调法 |
|---|---|---|
| `DockSnapDistance` | 20 | 距边缘多少像素内松手算贴边。调大更容易吸附，调小需要更"用力"贴 |
| `DockPeekPx` | 6 | 收起后露出的窄条宽度。调大更显眼，调小更隐藏 |
| `DockCollapseDelayMs` | 600 | 鼠标离开后多久收起。调大不容易误收，调小更"自动" |
| `DockAnimMs` | 160 | 动画时长。调到 0～60 会显得生硬，200～300 更舒缓 |
| `DockAnimFrameMs` | 15 | 帧间隔（≈66fps） |
| `DockHoverPollMs` | 120 | 悬停轮询间隔。调小响应更快但更耗 CPU（50ms 也几乎无感） |
| `DockClickGuardMs` | 500 | 展开后吞掉点击的时长，防止"双击切换键盘"被误触发 |

## 5. 多屏与分辨率处理

| 场景 | 处理方式 |
|---|---|
| **多显示器** | 吸附那一刻用 `Screen.FromPoint(Cursor.Position)` 锁定目标显示器，把 `DeviceName` 记在 `_dockScreenDevice` 里，之后一直用它 |
| **⚠️ 为什么必须锁定** | 窗口贴**屏 B 的左边缘**收起后会滑到屏幕外，中心点正好漂进左边那块**屏 A**——如果每次都按"窗口中心"重算屏幕，就会取到屏 A 的工作区，位置算错。这是实现过程中发现并修掉的真实缺陷 |
| **显示器被拔掉 / 分辨率变化** | 订阅 `Microsoft.Win32.SystemEvents.DisplaySettingsChanged`，切回 UI 线程后按当前状态重新贴合；锁定的 `DeviceName` 找不到了就自动回落重新判定 |
| **任务栏** | 一律用 `WorkingArea`（已排除任务栏），不会藏到任务栏底下 |
| **工作区比窗口还小**（极端分辨率） | `peek` 取 `Min(DockPeekPx, 窗口尺寸)`，退化为完整显示，不会把窗口整个推出屏幕 |
| **贴边时的纵向/横向对齐** | 沿边缘贴但不强制居中，保留用户拖到该边时的位置，只做 `Clamp` 保证整体落在工作区内 |
| **DPI** | 进程是 DPI-unaware（`app.manifest` 里未开启 dpiAware），`Cursor.Position` 与 `Bounds` 同处系统虚拟化坐标系，不存在物理/逻辑像素不一致问题 |

### 建议的实测清单

- [ ] 拖到屏幕左/右/上/下边缘松手 → 应吸附贴边

## 8. 已知限制

1. **收起后无法用鼠标直接拖走**：窄条只有 6px，要先悬停展开才能拖。这是"贴边隐藏"的常规行为（QQ / 微信同理），如需改变可把 `DockPeekPx` 调大。
2. **窄条不可点穿透**：收起状态下宽 6px 的窄条会覆盖屏幕最边缘 6px 的区域（其中不透明的那部分会吃掉点击），如果你有必须点在屏幕最边缘 6px 内的操作，把 `DockPeekPx` 调小。
3. **`WS_EX_NOACTIVATE` 保持不变**：窗口仍然不会被激活，因此悬停展开不会抢走当前应用的焦点，这是符合预期的。
4. **动画用 `Location` 逐帧插值**：160ms / 11 帧，每帧一次 `SetWindowPos`。开销可忽略，但在极端省电模式下（如某些车机的降频策略）可能略有卡顿，届时把 `DockAnimFrameMs` 调到 20～25 即可。
