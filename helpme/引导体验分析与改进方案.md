# helpme 首次引导（First-Run Onboarding）体验分析与改进方案

> 分析对象：`C:\weasel\helpme\helpme\`（WinForms，net4.8，AssemblyName `helpme`，窗口标题「小白T9输入法 HelpMe v2.1」）
> 分析方式：通读 `Form1.cs` / `Form1.Designer.cs` / `Program.cs` / `helpme.csproj`，并用 `dotnet build` 实编译验证结论。
> 结论先行：**当前引导只有一条脆弱的线性路径，且"成功"的判定完全靠不住；但它已经做对了最难的一件事——把能自动化的都自动化了。**

---

## 一、现状：这套引导实际是怎么跑的

### 1.1 入口链路

安装包用 `.onInstSuccess` + `.onGUIEnd` 实现了「零点击」——装完自动打开桌面上的 `小白T9输入法HelpMe.lnk`
（`output\install.nsi` 第 389 行建快捷方式、第 395/405/411 行负责自动拉起）。所以 **helpme 就是首启引导本体**，这一点设计是对的。

### 1.2 窗口结构（`Form1.Designer.cs`）

单窗口、三栏，`ClientSize = 838×348`：

| 区域 | 控件 | 作用 |
|---|---|---|
| 左栏 `panelLeft`（380px） | `lblTitle`（步骤标题）、`btnSwitch`（唯一按钮，330×62）、`pictureBox2`（95×164 梗图「看右面」）、`pictureBox1`（229×178 输入法列表截图，红圈标出「小白T9输入法」）、`textBox1`（底部试打框） | 面向用户 |
| 右栏 `panelRight` | `lblLogHint` + 黑底绿字 `txtLog`（Consolas 10F，带时间戳） | 面向开发者 |
| 最右 | `adPanel` 190px 捐助面板（微信/支付宝/淘宝三码）+ `btnToggleAd` 折叠钮 | 变现 |

### 1.3 引导状态机（`Form1.cs:555-584` `SetStep`，共 4 态）

```
构造函数(56-72) → SetStep(1) → [用户点 btnSwitch_Click_1(334-378)]
   ├ EnsureT9s2tRunning()          拉起 t9s2t\t9s2t.exe（含 Thread.Sleep(2000)）
   ├ SetStep(2) + AppendLog
   ├ 拉起 numkeyboard.exe
   ├ keybd_event 按下 Win（不松）→ 空格 → 松开空格     ← 模拟 Win+空格
   ├ SetHook() 装全局低级鼠标钩子（WH_MOUSE_LL）
   ├ actionTimer(15s) 启动
   └ ShowArrow() 窗口右侧画出闪烁大红箭头 + 「请在右下角选择【小白T9输入法】」
                    ↓
     ┌──────── HookCallback(381-429)：任意左键/右键按下 = 成功
     │            松 Win → 卸钩子 → 激活窗口 → textBox1 聚焦 → SetStep(3) → ExecutePostSwitchTasks(481)
     └──────── ActionTimer_Tick(431-442)：15 秒没点击 = 也当成功
                  重置 → 松 Win → 隐藏箭头 → SetStep(0) → 同样执行 ExecutePostSwitchTasks

ExecutePostSwitchTasks(481-509) 无差别做 5 件事：
   ① 拉起 WeaselServer.exe  ② 开 NumLock  ③ 关 CapsLock
   ④ EnsureChineseMode() 按 Shift 切中文(511-529)  ⑤ 模拟小键盘敲 "64486"(531-542)
```

`pictureBox1` 是一张**静态截图**：系统输入法列表长什么样、红圈圈住「小白T9输入法」。它和右侧大箭头配合传达「去屏幕右下角找这个列表」。

## 二、不足：按严重程度分级

### 🔴 A. 引导机制本身是"脆"的，而且会"假成功"

| # | 问题 | 位置 | 后果 |
|---|---|---|---|
| A1 | **成功判定完全不校验结果**。`HookCallback` 里只要收到 `WM_LBUTTONDOWN` 或 `WM_RBUTTONDOWN` 就判成功，不判断点在哪、选没选中 | `Form1.cs:383` | 用户点桌面、点别的窗口、甚至按右键，都会被当成"你选好了"，程序继续往下跑 |
| A2 | **超时也当成功**。15 秒没点击不是提示重试，而是直接执行 `ExecutePostSwitchTasks()` | `Form1.cs:431-442` | 用户还没弄明白，程序就说"完成！"，**并且顺手改了 NumLock/CapsLock/输入法状态**——留下"它自己乱动我电脑"的印象 |
| A3 | **`isWinPressed` 赋了值从未被读** | `Form1.cs:43`，实编译报 `CS0414` | 说明"按住 Win 等用户点选"这个关键语义根本没落地，Win 键的释放只靠点击/超时两条路，任何一条异常都会**把用户的 Win 键卡在按下状态** |
| A4 | 依赖全局低级鼠标钩子 + `keybd_event` 模拟按键 | `Form1.cs:14-15, 374, 472-479` | 在 UAC 提权窗口、安全软件、部分游戏/远程桌面下会被拦或失效；对新手来说这是"点了没反应"的头号来源 |
| A5 | 箭头是**窗口内固定角度**画的，跟系统输入法浮窗的真实位置无关 | `Form1.cs:607-614`（起点 25%/25% → 终点 80%/80%） | 多屏、任务栏竖排/置顶、输入法列表弹在别处时，箭头指向错误 |
| A6 | 闪烁箭头有**10 秒空窗**：`blinkTickCount > 250 × 40ms = 10s` 就自动隐藏，但超时定时器是 15 秒 | `Form1.cs:266, 275, 250` | 第 10–15 秒之间屏幕上**什么指引都没有**，用户更慌 |

### 🟠 B. 新手认知门槛：术语、文案与信息架构

| # | 问题 | 位置 |
|---|---|---|
| B1 | 满屏术语：「Win+空格」「输入法列表」「右下角」「T9」，没有一个配有"在图里哪个位置"的标注 | `lblTitle.Text`、`ArrowOverlay.OnPaint` 的文案 |
| B2 | **右侧黑底绿字日志是给开发者看的**：时间戳、`【启动】`、`【警告】`、`【失败】异常: System.xxx` 全暴露给新手 | `Form1.cs:294-299` + `txtLog` 样式（Designer `:61-65`） |
| B3 | 真正的用户提示只挤在 `lblTitle` 两行 + 按钮文字里；日志区占了 458px 宽，比引导区还显眼 | 版面比例失衡 |
| B4 | **没有进度感**：只有"第 1 步 / 第 2 步 / 完成"，没有 `1/4`、没有勾选态、没有剩余步数 | `SetStep` |
| B5 | 按钮用 `①②` 抽象符号代替动词，"② 请在右下角选"是**祈使句写在按钮上**，但点它并不会"选"，只会重跑一遍流程 | `Form1.cs:563,569` |
| B6 | 第 3 步按钮文案写「① 再练一次」，但 handler 仍是 `btnSwitch_Click_1`，实际会**重跑整套 Win+空格 + 钩子流程**，不是"再练打字" | `Form1.cs:575` + `Form1.Designer.cs:47` |
| B7 | 无音效、无动效、无高亮，全部靠文字静态呈现；`pictureBox2` 是「看右面」梗图，属于开发者幽默，对目标用户（中老年/小白）不加分反而占位 | `Form1.cs` DESIGNER `:126-134` |

### 🟡 C. 内容覆盖范围太窄

现在只教了一件事：**"把输入法切过去"**。以下全部缺失：

1. **T9 输入法怎么打字**——数字键 ↔ 拼音的对应、怎么选字、怎么翻页、常用符号在哪、中英怎么切。这是新手最需要的，却一个字都没有。
2. **`t9s2t`（语音转文字）**——只被悄悄拉起，用户完全不知道它是什么、怎么用、要不要一直开着。
3. **`numkeyboard`（数字小键盘）**——同上，拉起后没有任何介绍。
4. **`WeaselServer`**——被自动启动，但用户不知道"托盘那个图标是它，别关"。
5. **常见问题**：没反应怎么办 / 怎么切回英文或原输入法 / 怎么卸载 / 卸载后残留 / 任务栏没图标。
6. **设置入口**：皮肤、词库、用户目录（`install.nsi:378-380` 明明建了 `userdir` / `weaseldir` / `update` 三个快捷方式，教程里完全没提）。
7. **"我已经会了，别再烦我"**：没有跳过、没有"不再显示"。

### 🔵 D. 无"首次"概念

没有落盘任何 `firstRunDone` 标记，**每次打开 helpme 都从第 1 步重来**；也不会判断"小白T9 是否已经是当前输入法"（若是，应该直接进试打/速览页）。
唯一持久化的是广告面板折叠态 `%APPDATA%\helpme_ad_state.txt`（`Form1.cs:53`）——**教程状态没存，广告状态存了**，优先级刚好反了。

## 三、改进方向

### 3.1 引导流程：从"单线 4 态"改成"向导 4 步 + 进度 + 可回退"

```
┌ 第 0 屏 欢迎（新增）
│  一句话说明 + 一张"我接下来会帮你做 4 件事"清单 + [开始设置] / [我自己来]
├ ① 环境自检（全自动，用户只看着）
│    拉起 WeaselServer / 拉起 t9s2t / 检查 numkeyboard / 读输入法列表
│    以动画逐项打勾：✓ 输入法服务已就绪 ✓ 语音工具已就绪 …
├ ② 切换到小白T9（唯一需要用户动手的一步）
│    真实浮窗定位箭头 → 点击 → **校验** → 成功才进下一步，失败给重试
├ ③ 打字体验（自动演示 + 用户试打）
│    自动输入一个用户一眼能懂的高频词并上屏 → 引导在 textBox1 里自己打一遍
└ ④ 完成 + 速览（新增）
     4 张卡片：常用按键 / 语音工具 / 数字键盘 / 遇到问题
     [重新引导] [打开设置] [以后不再显示]
```

进度指示：顶部 4 个圆点 `● ● ○ ○` + 文案「第 2 步 / 共 4 步」。
每步右上角保留「上一步」，「第 0 屏」与「第 4 屏」提供跳过。

### 3.2 交互步骤：把"看起来成功"换成"验证过成功"

这是**投入产出比最高**的一项改动。

**(a) 点击后校验当前输入法是否真的是小白T9**

```csharp
// 伪代码：遍历系统已装输入法，找到小白的 HKL
foreach (var hkl in GetKeyboardLayoutList())
{
    var sb = new StringBuilder(64);
    ImmGetDescription(hkl, sb, 64);          // 拿输入法描述
    if (sb.ToString().Contains("小白") || sb.ToString().Contains("Weasel"))
        weaselHkl = hkl;
}
// 校验：前台窗口当前用的 HKL 是否等于 weaselHkl
var fg = GetForegroundWindow();
var cur = GetKeyboardLayout(GetWindowThreadProcessId(fg, out _));
bool ok = (cur == weaselHkl);
```
判定为假 → 不推进，改为提示「好像还没选中，再看一眼右下角那个列表 → [再试一次] [手动看图]」。

**(b) 箭头指到真实浮窗，而不是窗口内画固定角度**

用 `EnumWindows` / `FindWindow` 找到 Win+空格 弹出的浮窗（类名 `Windows.UI.Core.CoreWindow` 或传统 `#32768` 弹出菜单），`GetWindowRect` 拿矩形，把覆盖层改成**独立无边框置顶透明窗口（`WS_EX_LAYERED | WS_EX_TRANSPARENT | WS_EX_TOOLWINDOW`）**，按屏幕坐标把箭头尾巴画在浮窗旁边、箭头头指向被选中的那一项。找不到浮窗时，降级为指向屏幕右下角任务栏语言区域。

**(c) 兜底路径：能自动就别让用户动手**

前述方案仍要用户点一下，是因为 `WM_INPUTLANGCHANGEREQUEST` 对 TSF 输入法不一定生效。正确做法是**先试自动**：

1. 首选 `ITfInputProcessorProfiles::ActivateLanguageProfile`（COM，Weasel 的 CLSID/LANGID/profile GUID 是固定的）→ 直接激活，**零交互**；
2. 失败则 `LoadKeyboardLayout("E0200804")` + `ActivateKeyboardLayout` → 再校验；
3. 再失败才走"箭头 + 人工点击 + 校验"。

把 `isWinPressed` 真正用起来：Win 键的释放放进 `try/finally`，且无论走哪条路都必须保证 Win 键松开（现在只在成功/超时两条路松，异常路径会卡键）。

**(d) 超时不再等于成功**

15 秒改为「还没好？→ 显示三个选项：**[再试一次] [我手动看图] [跳过这一步]**」，绝不在用户没确认的情况下执行 `ExecutePostSwitchTasks`。

**(e) 副作用先问再做**

`ExecutePostSwitchTasks` 里改 NumLock / CapsLock / 按 Shift 切中文，都加一个首次询问 + `以后别再自动改` 复选（写进 `%APPDATA%\helpme\state.json`）。日志文案从「【自动】已帮你打开小键盘」改为用户语言：「小键盘已打开（打字要用到它）」。

### 3.3 文案呈现：去术语、动词化、图标化

| 现在 | 建议 |
|---|---|
| 「第 1 步 / 点下面这个蓝色按钮」 | 「先点一下这个按钮，剩下的我来」 |
| 「在方框里点『小白T9输入法』」 | 「右下角弹出一个列表了，点第二个『小白T9输入法』」（**带序号 + 图标缩略图**） |
| 「请在右下角选择」 | 「看屏幕**右下角**（时钟旁边），出现这个框就点它 ↓」+ 真实截图缩略图 |
| 箭头旁的 `请在右下角选择\n【小白T9输入法】` | 缩短为「点这里 ↓」，把说明放到旁边的气泡里 |
| 按钮 `① 点我开始` / `② 请在右下角选` | `开始设置` / `我点好了` / `再试一次` / `跳过` |
| 黑底绿字 `【失败】异常: ...` | 主区只留 `遇到一点问题` + 图标 + 一个按钮；技术日志折叠到「查看详细信息」 |

**信息架构调整**：把右栏从"日志"改成"状态清单"（4 行，每行 = 图标 + 一句话 + 状态），技术日志降级为可折叠面板，默认收起。左右栏宽度比从 `380 : 458` 改成引导区占主导（如 `460 : 380`）。

**新增视觉反馈**：步骤切换用淡入 + 高亮圈（现在只有箭头有闪烁）；完成时给一个明显的绿色对勾动画。

### 3.4 内容覆盖：补齐 5 块

1. **第 0 屏的"我要帮你做的事"清单**——让用户在动手前就知道后面还有几步。
2. **10 秒学会 T9 打字**卡片：数字键 ↔ 字母映射图（`2ABC 3DEF 4GHI 5JKL 6MNO 7PQRS 8TUV 9WXYZ`）、怎么选字、怎么翻页、中英切换。**这是目前最大的内容缺口。**
3. **三个工具的一句话介绍 + 开关**：`t9s2t`（按住说话转文字）、`numkeyboard`（屏幕数字键盘，鼠标也能打字）、`WeaselServer`（托盘小图标，别关）。
4. **常见问题（FAQ）折叠面板**：没反应？/ 怎么切回英文？/ 怎么改皮肤和词库？/ 怎么卸载（含"在设置→应用里卸载，或跑卸载程序"）？/ 装完没图标？
5. **设置入口按钮**：直接调用安装包已建好的 `WeaselServer.exe /userdir`、`/weaseldir`、`/update`（`install.nsi:378-380` 已有快捷方式，教程里接上即可）。

### 3.5 "首次"检测与安静模式

- `%APPDATA%\helpme\state.json` 存 `{ firstRunDone, adCollapsed, autoFixInputState, lastRunAt }`；
- 第二次打开：直接进「完成 + 速览」页，顶部给一句「你上次已经设置好了，可以直接打字」+ `[重新引导]`；
- **首次引导期间强制折叠捐助面板**（`_adCollapsed = true`），引导结束后再恢复用户上次的选择；
- 启动时若检测到小白T9已是当前输入法 → 直接跳到试打页。

### 3.6 顺带修掉的工程问题

先修 `Form1.cs:80` 的 `_imgPdd` → `_imgTaobao`，并把资源名改成 `helpme.Properties.taobao_qrcode.png`（与 `helpme.csproj:75` 对齐）。**已修复**（见文末"修复记录"）。同时把三个静默 `catch { }` 换成了会写日志的读图方法 —— 否则 E1/E2 这类"资源改名漏改"完全无声无息，这次就因此藏了三个月。

**顺带发现的两点（未改）**：
- `helpme\helpme\` 根目录还躺着三个**未被 csproj 引用**的 png（`wechat_qr.png` 448908B、`alipay_qr.png` 109948B、`taobao_qrcode.png` 47604B）。其中根目录 `wechat_qr.png` 与 `Properties\wechat_qr.png`（109581B）**内容不同**，是历史遗留的错版图 —— 建议清掉，免得将来又照着它排查（参考本项目"内嵌资源 vs 运行时覆盖文件是两份独立文件"的老坑）。
- `adPanel_Paint` 最后一行文案的绘制位置是 `y3txt + 16 ≈ 341.6`，而 `adPanel.Height` 被 `ApplyAdState` 强制设为 `ClientSize.Height = 348` —— 7pt 文字高约 9px，**末尾几乎贴到面板底边**，换字体或缩放后容易被裁。建议把面板高度或该行位置留出余量。

## 四、哪些环节能做到"不读说明也能完成首次设置"

判断标准：**用户只需看屏幕、不需要理解任何术语，就能走完。**

| 环节 | 谁来完成 | 判定依据 | 关键实现 |
|---|---|---|---|
| 找到教程 | 安装器 | ★ 完全自动 | `.onInstSuccess`+`.onGUIEnd` 自动打开桌面 HelpMe（**已实现**，`install.nsi:395-412`） |
| 拉起输入法服务 / 语音工具 / 数字键盘 | 程序 | ★ 完全自动 | `EnsureT9s2tRunning` + `ExecutePostSwitchTasks`（**已有**，需加"是否成功"回显） |
| 环境自检（NumLock / CapsLock / 中英状态） | 程序 | ★ 完全自动（建议加"以后别再改"开关） | `ExecutePostSwitchTasks:493-499`、`EnsureChineseMode:511-529` |
| **切换到小白T9** | **用户点一下**（唯一一步） | ★★ 需要"看得懂的画面"，但**不需要读文字** | 真实浮窗定位箭头 + 序号 + 缩略图 + 点击后校验 + 失败重试（见 3.2） |
| 试打验证 | 程序演示 + 用户跟随 | ★★ 不需要读说明 | 自动输入高频词并上屏 → 光标已自动落在试打框（`ExecutePostSwitchTasks:414` 已有"光标放回测试框"） |
| 知道要关机/重启吗 | 程序 | ★ 完全自动 | 安装包已启动服务，无需重启；应在完成页明确写「不需要重启」 |
| 遇到问题怎么办 | 程序 | ★★ 图标按钮，不读文字 | 「没反应？点这里」一键重试 / 一键切手动图文 |
| 卸载 / 切回原输入法 | 程序 | ★★ 图标按钮 | 完成页放两个图标按钮直达 |

**一句话总结**：真正需要用户动手的**只有"在列表里点一下小白T9"这一个动作**。其余环节现在就已经是自动的（这是现有设计最大的优点），缺的是**把它们的结果验证出来并可视化地回显给用户**，以及**给那唯一一步配上不会指错地方的箭头和一遍校验**。
